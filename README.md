# Quick Note

轻量 Markdown 笔记软件。目录即仓库（vault），文件保持纯 `.md`，可与 Obsidian 及
quick-daily-note 插件共用同一个仓库并同步。

技术选型与架构决策见 [docs/技术选型.md](docs/技术选型.md)。

## 进度

**M0 外壳验证（已完成）** — 详见 [docs/M0-实现说明.md](docs/M0-实现说明.md)

- Tauri v2 + React 19 + CodeMirror 6 骨架
- Rust 侧仓库操作：列举 `.md`、读取、写入；隐藏路径（`.obsidian` 等）与非 md 文件自动跳过；路径越界拒绝
- 自动保存（停止输入 1.2s）+ `Ctrl/Cmd+S`；内容未变则不触碰文件（mtime 不变）
- 界面显示换行符风格、BOM、字节数、内容 SHA-256，并提供「校验往返」按钮现场验证

**M1 Live Preview（已完成）** — 详见 [docs/M1-实现说明.md](docs/M1-实现说明.md)

- Live Preview 装饰层：标题、粗体/斜体/删除线、行内代码、链接、复选框（可点击写回源码）、
  列表圆点、分割线、引用、围栏代码块
- 表格渲染成真正的 `<table>`：单元格内的行内语法与列对齐都会解析，点击表格即可切回源码编辑
- Mermaid 流程图等渲染成图，**按需加载**（不进主包，实测 6 个 chunk 共 832 KB）；
  图定义写错时只显示错误提示，不影响编辑器
- 图片真实加载（Tauri asset 协议 + 运行时目录授权），相对路径按笔记所在目录解析；
  文件缺失时降级成标签
- **支持 Obsidian 的 wiki 语法**：`![[图片.png]]`（含 `|宽度` / `|说明` 写法）、
  `[[笔记]]` / `[[笔记|别名]]`；wiki 目标按文件名在全库查找，不是相对路径
- **内容嵌入（transclusion）**：`![[某笔记]]` 把目标笔记内容渲染进来，支持
  `#小节`（取到下一个同级标题）与 `#^块标识`（取所在段落）。嵌入内容里的原始 HTML 会被
  转义——内容可能来自同步，而这个应用能写文件，不能当可信 HTML 渲染
- **额外 Markdown 语法**：裸链接 `https://…`、行内公式 `$...$`（KaTeX，按需加载）、
  `==高亮==`、`%%注释%%`（整段隐藏）、`#标签`、callout（`> [!note]` 标题，带类型配色与图标）、
  setext 标题、手写 HTML（`<br>`/`<font>`/`<img>` 等行内标签与 HTML 块）。
  HTML 会经 DOMPurify 清洗后渲染——**清洗只作用于显示**，文件内容与同步哈希不受影响
- **Ctrl/Cmd+点击链接用系统浏览器打开**（只认 http/https；不在应用内导航，
  那会把整个应用带走）
- **主题**：浅色 / 深色 / 跟随系统，配色全部走 CSS 变量
- **文件树反映仓库真实结构**：目录（**含空目录**）与非 Markdown 文件都会列出；不含笔记的
  目录默认收起（只放附件的目录不会刷满侧栏）
- **文件管理**：新建文件夹（侧栏按钮）、**新建日记**（侧栏「＋日记」，按日期命名）、
  **新建笔记 / 重命名 / 删除**（右键菜单——新建落在选中目录或选中文件所在目录）。新建时
  名称缺 `.md` 自动补、可写 `子目录/名称`、重名自动加序号（不覆盖）、非法名称被拒绝并提示；
  落点是「当前打开笔记所在目录」，界面上会写明。重命名会**同步更新其他笔记里的 wiki 引用**
  （wiki 按文件名解析，不改就等于引用静默失效）。删除是**移入仓库内的 `.trash`**、可以找回
- **粘贴附件**：粘贴图片/文件自动保存到附件目录（默认 `attachments`，可设置）并在光标处
  插入链接。图片用 Obsidian 风格的 `Pasted image <时间戳>.png` 命名；重名自动加序号，
  **不覆盖已有文件**。链接写法可选 wiki（`![[图.png]]`，默认）或 markdown
- **文件监听**：外部程序（Obsidian、同步进程、其他编辑器）改动文件后界面自动跟上；
  有未保存编辑时弹冲突提示，不会静默覆盖
- 光标所在行显示源码；Live Preview / 源码 双模式切换（用 Compartment，保留撤销历史）
- 围栏代码块带语法高亮，语言包按需加载

**多标签页与目录（0.3）**

- **多标签页**：每个标签独立的光标、滚动位置与撤销历史（各存一份 EditorState），

**M3 云同步（已完成）** — 详见 [docs/M3-实现说明.md](docs/M3-实现说明.md)

- **与 Obsidian 插件共用同一个云端仓库**（daily-sync 服务）：账号密码登录换 JWT、
  401 自动续期换新令牌（refreshToken 一次性轮换，30 天滚动），游标/分页/幂等推送照抄插件
- **哈希口径已核实并对齐**（技术选型里列为 M3 阻断项的那一条）：Obsidian 的
  `Vault.prototype.read` 是 `readFile(utf8)` 后**剥掉 BOM**、换行符不做任何规范化，
  所以同步哈希取"**已剥 BOM 的正文**"，CRLF/CR/尾随换行原样参与哈希。
  插件 `data.json` 里存着的 9 个文件哈希逐条复核一致。**磁盘上的 BOM 仍然原样保留**——
  BOM 只是不参与哈希与上传，写回依旧是字节精确的
- **冲突策略**：本地改动胜出并回推；云端删除时本地没动过就跟删（进仓库内 `.trash`，
  可找回），本地改过就复活；双边都改过时界面列出冲突文件。唯一与插件不同的地方是
  "本设备不认识这个文件"时**本地胜**——否则一次「重置同步状态」会让云端成片覆盖本地
- **本地删除会同步出去**，而且**改日记目录不等于删除**：判定时区分"文件真的没了"
  与"只是离开推送范围"，后者绝不打墓碑（否则改一次目录就会删掉云端旧目录的整批笔记）
- **待办走虚拟文件**（不落盘、不进仓库）：按 `id` 条目级合并、`updatedAt` 新者胜、
  墓碑保留 30 天；云端由网页端或 Obsidian 加/勾/删的条目会回流，合并结果回推
- **后台同步**：改动后 3 秒防抖推送、每 5 分钟一轮、启动后 5 秒首同步；状态栏显示
  同步状态与时间，点一下立即同步；游标异常时可重置游标重拉
- **凭据与状态只在本机**（应用配置目录的 `sync-state.json`，含密码与令牌，**不进仓库**）；
  状态文件坏了**不静默降级**，而是暂停同步并给出「重新读取 / 重置同步状态」两个出口
- **附件同步尚未做**（见下），但游标已把附件的版本号一起吃掉，将来接上不会漏

- **检查更新**：设置面板手动检查 GitHub Releases（发现新版本一键打开发布页）；
  应用版本随 tauri.conf 走
- **附件同步（M3 补全）**：**按引用扫，不按目录扫**——只同步被范围内笔记引用到的
  附件（`![[图.png]]` 与 `![](attachments/图.png)` 两种写法都认，围栏/行内代码里的示例
  不算），没被引用的图片不上云，不镜像无用的二进制；本地缺的图**按文件名去云端补**，
  落到服务端 `X-Attachment-Path` 指定的路径（同目录优先 → 最短路径 → 字典序，与插件
  和服务端同一套解析）；上传与下载都有每轮上限（20 个 / 50MB），被推迟的下轮继续；
  白名单 png/jpg/jpeg/gif/webp/pdf（刻意不含 svg），上限 10MB
- **附件目录配置统一**：粘贴附件目录（`pastedImageFolder`）从本机设置**迁移到库内配置**，
  与 Obsidian 插件共用同一个键、同一份文件——两边换用不用设两次，同步一开多台设备自动
  一致。旧版本存本机的自定义值会在打开仓库时一次性迁过去
- 设置面板现在**可以滚动**（内容超过窗口高度时面板内部出滚动条）

M5 打包与体验；阅读视图也未实现。

## 核心不变量：字节精确往返

同步协议（daily-sync）用内容的 **SHA-256** 判断文件是否变化。因此本项目的硬性约束是：

> 读写链路不得对文件内容做任何隐式改写。换行符、BOM、尾随换行必须原样保留。

一旦编辑器把 CRLF 规范化成 LF、或吞掉 BOM，所有未改动的文件都会被判成"已改动"，
制造大量虚假冲突。为此：

- Rust 侧不做任何内容规范化，只剥离 BOM 并报告其存在，写回时补上；
- 编辑器用 `EditorState.lineSeparator` facet 对齐文件的换行符风格，**序列化必须用
  `state.sliceDoc()`**——`state.doc.toString()` 固定用 `\n` 拼接，会悄悄改写 CRLF 文件；
- 写入前比较内容，一致则不落盘，避免无谓地更新 mtime 触发同步连锁。

### 验收

```bash
./scripts/verify-all.sh    # 逻辑层：磁盘 ↔ 字符串 ↔ 编辑器状态
./scripts/verify-gui.sh    # 界面层：启动真实应用，用 CDP 断言 DOM 并模拟真实输入
```

`verify-all.sh` 一条命令跑完：

1. 类型检查（能抓到 Node 类型擦除测试抓不到的类型错误）
2. 重建测试仓库并记录内容哈希基线
3. Rust 集成测试：磁盘 ↔ 字符串无损（BOM、CRLF、仅 CR、混合换行、无尾随换行、路径越界），
   以及新建/重命名/删除与「配置文件可选读取」
4. 由 Rust 导出换行符探测结果，作为编辑器层测试的**地面真值**
5. 编辑器层测试：字符串 ↔ CodeMirror 状态无损
6. Live Preview 装饰层测试：语法标记隐藏、样式、小部件、表格（含单元格行内语法与对齐）
7. 额外行内语法扫描测试：公式 / 高亮 / 注释 / 手写 HTML 的边界
8. 附件命名与链接测试
9. 日记与日历的纯逻辑测试（146 项）：ISO 周号跨年、命名与发现、模板占位符、日历网格、
   统计口径、待办墓碑与顺延、**库内配置的补丁式写回**
10. 云同步的纯逻辑测试（124 项：冲突决策、状态兜底、快照合并、哈希口径，以及附件的白名单、stamp 旁路缓存与每轮下载预算）：**冲突决策的每个分支**、同步状态的深拷贝与坏值兜底、
    待办快照的稳定性与条目级合并、哈希口径与 Node `createHash` 互校、范围判定与 URL 归一化
11. 表格与大纲的纯逻辑测试：管道对齐（CJK 显示宽度）、行列增删不丢内容、单元格区间、标题提取（围栏跳过、setext 区分）
12. 比对基线，确认整个过程没有改动任何文件

`verify-gui.sh` 会先以独立 identifier 构建一个**测试变体**（WebView2 使用独立数据目录），
再启动应用，通过远程调试端口读取**渲染后的 DOM**，并用真实鼠标与键盘完成：

1. 打开/编辑/保存后 CRLF 依然完整
2. Live Preview 的渲染与模式切换（含表格、Mermaid、图片真实加载、收尾围栏压缩）
3. 点击复选框写回源码并落盘
4. 文件监听：外部改动在无编辑时自动采纳、有编辑时弹冲突提示（两个选项都可点）、
   外部新建文件出现在文件树里
5. 粘贴附件
6. 新建/重命名/删除文件与文件夹
7. 额外语法渲染与主题
8. 日记与日历（79 项）：日历结构、单击与双击的区别、当天日记栏（篇数/打开/⋯ 菜单/
   ＋新建建出第二篇）、顺延全流程、待办增删勾选落盘、双击建周记、双击建日记并断言模板展开、
   **插件专有键在整轮读写后仍在**
9. 云同步（40 项）：**对着一个桩后端**（真实的 HTTP 服务，跑完即关）配置并点「立即同步」——
   首次推送的内容 CRLF 原样、BOM 不上云而磁盘保留、范围外的文件不推、状态里记的哈希与
   云端内容同口径；拉取/采纳/墓碑删除；本地改动 3 秒防抖自动推；双边改动的冲突提示与本地胜；
   待办快照推送与云端回流（含写回库内配置）；游标吃掉附件版本号；refresh 失效 + 密码错的
   凭证提示；改回正确密码后恢复。**桩后端是刻意的**：验收要在没有网络与 Docker 的机器上
   跑得完，而这里要验的正是字节与状态码的边界

结束后自动还原被改动的文件并比对基线。**基线现在把非隐藏的 `.json` 也算在内**——
M2 之后应用会写库内配置，它被写坏（丢掉插件键）比某篇笔记被改写严重得多，
而它以前恰好不在守护范围内。

> 用独立 identifier 有两个原因：测试不再读写你日常使用的应用配置；即使本机有残留实例锁住了
> 正式数据目录，测试也能跑。副作用是 `target/release/quick-note.exe` 会变成测试变体——
> 需要正式二进制时重新跑 `npm run tauri build -- --no-bundle`。

**两层测试缺一不可**：装饰层的单元测试能精确断言区间与类名，却测不出 CM6 对插件的运行时
限制（块级装饰、替换换行符——违反会让编辑器整体白屏）；GUI 测试能发现白屏与事件失效，
但定位不到具体原因。两个层面各自抓到过对方的漏网之鱼，详见
[docs/M1-实现说明.md](docs/M1-实现说明.md)。

> 测试脚本刻意不复刻换行符探测逻辑。此前的复刻版把 CRLF 误判为 LF，却因为
> LF 分隔符下 `\r` 会作为普通字符留在行内而"通过"——属于假阳性。现在真值只有
> Rust 一个来源（`cargo run --example dump-detect`）。

### 内存基线

```bash
powershell -ExecutionPolicy Bypass -File scripts/measure-rss.ps1
powershell -ExecutionPolicy Bypass -File scripts/measure-rss.ps1 -ProcessName Obsidian
```

输出工作集、私有提交、私有工作集三个口径。**三者常给出矛盾结论**：工作集重复计算
Chromium 共享页，私有提交包含已换出到页面文件的部分，跨应用对比建议用**私有工作集**。
有多个同名实例时脚本只测最新那个（要指定用 `-ProcessId <pid>`），避免把多实例的内存
加在一起得出虚高数字。已测数据与结论见 [docs/M0-实现说明.md](docs/M0-实现说明.md)
与 [docs/M1-实现说明.md](docs/M1-实现说明.md)。
