# M2 实现说明：日记与日历

M2 的目标是「按日期写日记」这一整条链路：日期即文件名、ISO 周记、模板占位符、
日历面板（含 W 周记列与打点）、本月/连续/今日字数、按日期分桶的待办与顺延。

它与 M1 有一个根本区别：**M1 只需要自己内部一致，M2 必须与 Obsidian 插件逐条对齐**。
两边共用同一个仓库，一旦命名规则或打点口径分叉，插件写的日记在 Quick Note 里就不算
「当天有日记」，反之亦然——不是显示问题，是同一份数据被劈成两半。

## 一、共用一份配置：库内 `quick-daily-note.json`

日记目录、日期格式、模板路径、待办数据都在仓库根的 `quick-daily-note.json` 里，
与插件共用。

### 为什么文件名不带点前缀

插件源码里写着这条注释（2.4.9 用过 `.quick-daily-note.json`，实测不同步）：

> 注意不能以 "." 开头：Remotely Save 源码的 isHiddenPath 检查会跳过任意点开头的路径段，
> 且该规则无配置开关可绕过。

所以它是个**可见**文件——会出现在文件树里（非 md，灰色不可编辑）。这是必要的代价。

### 补丁式写回：只动我们管的键

这份文件里有大量 Quick Note 不认识的键：`emailAccessKey`、天气、提醒时间、背景、
各种开关。所以实现上：

- 解析时保留原对象的**全部键与键序**（`JSON.parse` 保序）；
- 写回时只改我们管的 8 个键，其余原样序列化；
- 已有键就地替换（键序不变），只有**新建文件**才按插件的键序排布。

反例是把配置建成一个 TS 对象再整份写回。那样用户插件里的邮箱 access key、天气城市、
提醒开关会在某次「改日记目录」时被静默清空。这不是理论风险——插件侧 `sync.ts` 就因为
`{ ...DEFAULT_SYNC_STATE }` 的浅拷贝共享默认 Map 踩过一次。

序列化用 `JSON.stringify(obj, null, 2)`，与插件逐字节一致（**无尾随换行**）。

### 解析失败就**禁止写回**

配置可能被手改、被同步进程写坏、或来自更早的版本。JSON 解析不出来时置 `broken`：

- 界面照常可用（按默认值渲染）；
- 任何修改都**不落盘**，并挂一条横幅说明；
- 横幅上给「重新读取」按钮，修好后能恢复。

理由很直接：我们读不懂这份文件，就无从知道里面有什么，写回去等于把用户的插件配置
整体覆盖掉。宁可这次改动不生效。

### 打开仓库不写文件

文件不存在时按默认值走，**不创建**。打开一个仓库就凭空造出配置文件，会让同步与
diff 多出一份「谁都没改过」的差异。首次真的改了设置才创建。

这一点也被 `verify-all.sh` 的基线守着：基线现在把 `quick-daily-note.json` 算在内，
只读一遍不该改动它的字节。

### 一个真 bug：内存状态与磁盘分叉

`serializeDailyConfig` 最初只写 `update` 里给出的字段，其余从 `state.raw` 复制。
而 `raw` 是**解析原样**、`state.todos` 是**规范化后**的——于是「只改日记目录」的一次
写回会把未升级的旧待办原封不动留在文件里，而界面显示的是升级后的版本。

被单元测试里那条「改设置时待办原样保留」抓住（两条断言分别读内存与磁盘，值不等）。

修法是让 `raw` 成为**规整后的形式**：解析时就把规范化后的 `todos` 与数字化的
`todosUpdatedAt` 写回 `raw`。于是「内存状态」与「将要写出的内容」定义上就一致，
序列化也不必再区分哪个字段来自哪里。

## 二、为什么引入 moment

`dateFormat` 是 **moment 格式串**（插件设置面板的原话：「使用 moment 日期格式」）。
共用一份配置就必须共用同一个格式化引擎。

手写一个「常用记号子集」是可行的，但在 `YYYY年M月D日` 或 `YYYYMMDD` 上会静默生成
插件找不到的文件名。更凶的是 ISO 周号：

```
2027-01-01  属于  2026-W53
```

`GGGG` 是 **ISO 周号年**，不是日历年。用 `YYYY` 拼 `WW` 会在每年第一周和最后一周错一格，
而周记文件名错一个数就等于丢一整周的记录。`startOf("isoWeek")` 与严格解析
`moment(s, format, true)` 同理——后者是必需的，宽松模式会把 `2026-09-14 日记` 里的
`2026` 也当成合法输入。

**代价**：moment 是 63,015 字节（minified）/ 20,272 字节（gzip），且落在**主包**里——
日历要算「今天」，`useDaily` 在启动时就会用到它，没法懒加载。主包因此从约 608 kB 涨到
670.7 kB（gzip 227.9 kB）。

**为什么不手写**：省下 20 kB gzip 换来一个「在用户改格式时才暴露、且表现为笔记分裂」
的失败模式，不划算。真要在意体积，正确的做法是给插件侧也提交同样的约定（改用 ISO 键），
而不是让一侧偷偷用一个不完整的实现。

## 三、命名与发现规则（逐条对齐插件）

| 项 | 规则 |
|---|---|
| 日记标题 | `<按 dateFormat 格式化的日期> <名字>`，名字必填（插件弹窗不允许空） |
| 日记路径 | `<folder>/<标题>.md`，目录不存在时自动逐级创建 |
| 周记标题 | `<ISO 周标识> 周记` → `2026-W37 周记` |
| 发现日记 | 目录**直接**子文件中 `日期.md` 或 `日期 ` 前缀，按文件名排序，多篇时取第一篇 |
| 发现周记 | `2026-W37.md` 或 `2026-W37 ` 前缀，同样取排序第一篇 |
| 打点 | 文件名第一个空格之前的部分；**周记排除** |
| 无模板时的内容 | `# <标题>\n`（与插件逐字节一致） |

几个容易做错、且**刻意与插件保持一致**的地方：

- **`2026-09-140.md` 不算 `2026-09-14` 的日记**（前缀后必须是空格或结束）。但它会作为
  独立的日期键进入打点集合——插件也是这样。不去「修好」它：打点集合一旦和插件不一致，
  两边看到的日历就不一样。真正兜住它的是统计处的严格解析。
- **`测试代码.md` 这类非常规命名**会贡献一个日期键（打点时不算任何一天，统计时被严格解析
  挡掉）。这是插件的行为，保持一致比"更干净"更重要。
- **不递归**：`日记/2026/09-15.md` 不算日记。
- **没名字的 `<日期>.md` 能被发现，但不会是插件创建出来的**（它要求必填名字）。用户手工
  建的文件要能认出来。

### 唯一的刻意差异：模板用函数替换

`String.replace` 的字符串替换里 `$&`、`$1`、`$$` 有特殊含义。日记名字里一旦出现这些
字符（如 `成本$&收益`），插件的字符串替换版本会把模板内容改坏。Quick Note 一律用
**函数替换**，属于严格的改进，不会造成两边内容不一致（除非名字里真有 `$&`，那时插件那侧
本来就是坏的）。

其余占位符语义完全照抄，包括两个反直觉的点：

- `{{week}}` 在**日记**模板里展开成**空串**（`vars.week` 为 undefined）；
- 未知占位符**原样保留**——留在文件里才能被用户看见，悄悄清掉反而像「模板没生效」。

## 四、日历面板

```
‹  2026年9月  ›                                今天
W  一 二 三 四 五 六 日      ← W 列：ISO 周号（去前导零），带周记圆点
36  31  1  2  3  4  5  6
37   7  8  9 10 11 12 13
38  14 15 16 17 18 19 20      ← 有日记的日子带圆点，选中日是 accent 实底
...
        本月 3 天  连续 2 天  今日 128 字
────────────────────────────────────────
当天日记（2）                          [＋ 新建]
2026-09-15 测试
2026-09-15 学习使用飞码            ⋯
────────────────────────────────────────
待办 · 2026-09-15                 (1 项未完成)
昨天有 1 项待办未完成          [顺延到今天]
```

- **固定 6 行 × 7 天**：切换月份时网格高度不跳动。首日固定周一（ISO 周），与 W 列
  必须一致，否则 W 格里的数字与那一行的日期对不上。
- **单击只切换选中，双击才打开/创建**。单击就打开的话，想看另一天的待办就得先跳走
  一篇笔记。这也是插件的行为。
- **W 列单击不做任何事**（周不属于任何一天），双击打开/创建该周周记。一周一篇、命名固定，
  所以不弹输入行，直接创建。
- **「当天日记（N）」列出选中日期已有的日记**，点名字打开；行尾 `⋯`（含右键）调出与文件树
  同一份菜单（重命名 / 删除）——复用同一份菜单是刻意的：M1 已经验证过"改名会同步 wiki 引用、
  删除进 .trash"，在面板里再实现一套弹窗等于把这些行为复制一遍。
- **没有日记的日期双击后就地展开输入行**问名字。插件用的是弹窗；这里做成输入行，与文件树
  的「＋笔记」同一套交互。已有同名文件时**直接打开，绝不覆盖**——日记是按日期命名的，
  重名意味着当天已有记录，覆盖等于删掉它。
- 「今天」按钮用来从别的月份跳回来（插件只有 ‹ ›，但翻走之后没有回来的路）。

### 同一天多篇

**「当天日记」栏的「＋ 新建」就是入口**：它始终可用（不因为当天已有日记而禁用），点开就地
输入名字即可再建一篇，篇数立刻变成「当天日记（2）」。双击某天仍然只在"当天没有日记"时才问
名字——已有日记时双击是"打开"，这与「单击选中、双击打开」是同一套语义。

（早先只能绕道文件树的「＋笔记」手写 `<日期> <名字>`：功能上能work，但要求用户知道文件名
规则，等于把内部约定暴露给用户。）

### 名字要校验，因为每条非法字符都对应一个静默失败

`validateDailyName` 挡掉路径分隔符、点开头、Windows 禁用字符。这不是形式主义的白名单：

- **含 `/`**：会被拼成**子目录**（`日记/2026-09-15 子/名字.md`）。而日记的发现只看目录的
  直接子文件，于是这篇日记在日历上既不打点、也算不进字数——"明明建了却没反应"。
- **点开头**：仓库枚举把点开头的路径段当隐藏项跳过（`.trash` 就是靠这条躲开文件树与
  索引的），文件在资源管理器里看得见，在应用里永远不出现。
- **Windows 禁用字符**：写盘直接失败，错误信息来自系统调用，读起来与"名字打错了"无关。

非法时**输入行保持展开**并就地给出原因，改一下就行，不用重新双击日期。
`../` 这类越界另由 Rust 侧的 `validate_rel` 兜底——两道都做是刻意的：JS 侧负责给出人能
看懂的原因，Rust 侧是安全边界（与附件命名的处理一致）。

### 与插件的视觉对齐

两边换着用，观感不该是两套东西。对齐的是：选中日 accent **实底**（面板上唯一"我在这里"的
指示，实底比淡底一眼可见）、悬停是淡底而不是描边、圆点 4px、统计居中、区块之间用分隔线、
待办行 16px 复选 + 8px 间距、`N 项未完成` 做成胶囊。W 列宽 24px、分隔线画在**网格容器**上
（绝对定位贯穿全高），不逐格描边——行高有差异时逐格描边会断成几截。

三处刻意的偏差，都是"照抄反而更差"的地方：

| 偏差 | 理由 |
|---|---|
| 多一个「今天」按钮 | 插件只有 `‹ ›`，翻走之后没有回到本月的路 |
| 用原生复选框（`accent-color`）而不是自绘 | 自绘要拿 CSS 画对勾，且要多维护一套状态；原生跟着系统走，可访问性也更好 |
| 复选框未选中时不显示行底 | 插件给已完成行加底色，这里只用删除线 + 变灰，少一层视觉噪音 |

截图核对过实际渲染（用 CDP `Page.captureScreenshot` 抓的侧栏，深色主题），
而不是靠猜 CSS——面板的观感问题只有看图才知道。

### 统计口径

| 指标 | 算法 |
|---|---|
| 本月天数 | 打点集合里能**严格解析**、且 `YYYY-MM` 等于**当前显示月份**的天数 |
| 连续天数 | 从今天往回数，遇到第一个没有日记的日子就停（**今天没写就是 0**） |
| 今日字数 | `content.replace(/\s+/g, "").length` |

字数这个口径要清楚它的含义：CJK 一字算一个，拉丁文按**字母**算（不是单词），标点计入，
emoji 这类星平面字符算 2（JS 的 `length` 是 UTF-16 码元数）。换成「按词计数」会让同一个
数字在两边显示成不同的值，比口径粗糙更难受。

## 五、待办

### 不写进日记的 Markdown

待办存在 `quick-daily-note.json` 的 `todos` 里，按日期分桶。理由不只是「与插件一致」：
勾选一条待办若意味着改写用户正在编辑的笔记，就会往同步协议里塞进无谓的内容差异；而待办的
结构化状态（id、修改时间、墓碑）本来也没法用一行 Markdown 表达。

### 数据模型：id + updatedAt + 墓碑

```ts
{ id, text, done, updatedAt, deleted? }
```

- **删除打墓碑，不是物理移除**：另一台设备没看到这次删除，会把这条当成「云端新增」又加回来。
- **墓碑不进渲染**（`liveItems` 滤掉），30 天后由同步侧清理。
- **旧格式迁移**（早期版本只有 `text`/`done`）：补齐 `id` 与 `updatedAt`，其中
  `updatedAt` 用**该侧最后一次修改时间**兜底，不是 `now`——否则「升级那一瞬间拿到当前
  时间」会让更旧的数据在同步合并时压掉别的设备。这条照抄插件的 `migrateTodos`。
- 迁移**只在内存里生效**，不因为「打开了仓库」就写盘。

### 昨日未完成顺延

提示只在「选中今天 + 昨天有未完成 + 今天尚未顺延过」时出现一次；顺延后今天就有了
「遗留」条目，提示自动消失，不会反复催促。

顺延本身有两条刻意的规则：

1. **源日期打墓碑 + 目标日期建新 id 的新条目**，不是把同一个 id 挪个地方。同一个 id
   出现在两个日期里，合并时无法判断它属于哪一天；打墓碑顺带解决了「顺延两次得到两份」
   ——第二次顺延时它已经不是 live 的了。
2. 目标条目一律 `done: false`，且文字前缀统一重写为 `[MM-DD 遗留]`。`stripCarryPrefix`
   会把叠加的多个前缀一并剥掉，否则连着顺延几天前缀会越滚越长，最后挤掉正文。

### 一个写代码时踩到的坑：显示顺序与下标

待办按「未完成在前」显示，但勾选要按下标回写。**下标必须是原始数组里的下标**：

```ts
// 错：先过滤墓碑再取下标 —— 只要删过一条，下标就整体错位，勾选会改到别人头上
liveItems(items).map((item, index) => ...)
// 对：从原始数组出发再过滤
(items ?? []).map((item, index) => ({ item, index })).filter((row) => !row.item.deleted)
```

单元测试里专门放了一条「首位是墓碑」的用例——那是最容易暴露错位的排列。

## 六、验证

```bash
./scripts/verify-all.sh    # 逻辑层，新增 146 项日记/日历断言
./scripts/verify-gui.sh    # 界面层，新增 79 项日历面板断言
```

### 单元层新增（`scripts/verify-daily.mjs`）

ISO 周号跨年、日期格式串、命名与路径与**名字校验**、发现规则（多篇/子目录/畸形名）、
模板五个占位符、日历网格（42 格连续无重复、跨年那一行的周标识）、统计口径、待办墓碑与顺延、
旧数据迁移，以及**库内配置的补丁式写回**。

配置那组断言是这次最要紧的：未知键保留、键序不变、改设置不动 `todosUpdatedAt`、
坏文件拒绝写回、模板开关只认真正的 `true`。

### 界面层新增（`scripts/gui-daily.mjs`）

结构（表头 8 格 / 6 行 W 格 / 42 格日期 / 恰好一格 today）、单击与双击的区别、
**当天日记栏**（篇数、列出文件名、点击打开、行尾 ⋯ 弹出的是文件树那份菜单、「＋ 新建」
在同一日期下建出第二篇且篇数跟着变）、顺延全流程（提示 → 点击 → 前缀 → 落盘 → 墓碑）、
待办增删勾选落盘、双击 W 列建周记、双击空日期建日记（模板四个占位符都断言到，含
"未知占位符原样保留"）、已有日记时打开而不覆盖、非法名字被挡住且磁盘上什么都没建、
插件专有键在整轮读写后仍在、设置面板读出库内配置。

### 两个测试写法上的决定

**测试不复刻任何日期逻辑。** 今天、周标识、周一日期都从 DOM 的 `data-date` /
`data-week` / `data-monday` 读出来，造日期的事交给应用自己。这个项目吃过一次亏：
测试脚本复刻换行符探测，把 CRLF 误判成 LF，却因为 `\r` 会留在行内而"通过"。
fixture 生成时用的是**系统自己的 `date` 命令**（`date +%Y-%m-%d`、`date -d yesterday`），
不是脚本里再实现一遍格式化。

**双击必须用浏览器级的两次点击**（`clickCount` 递增的 mousePressed/mouseReleased 各两次），
不能只 dispatch 一个 `dblclick` 事件——「单击只选中、双击才打开」正是这次要验证的接线，
凑出来的事件测不到它。

### fixture 里的一个撞车

`make-test-vault.sh` 会按当天日期生成「今天」和「昨天」两篇日记。**昨天那篇必须带名字**：
不带名字就是 `2026-09-14.md`，而它正好会等于第 1 条固定的 fixture（当运行日恰好是
2026-09-15 时），把那篇的内容覆盖掉——换行符探测与文件管理的测试全都依赖它。

### 基线的口径也补了一处

## 八、待办与遗留

- **待办的合并（merge）没做**，属于 M3：`buildSnapshot` / `parseSnapshot` / `mergeTodos`
  与 `daily-sync-todos.json` 快照都还没移植。数据模型（id/updatedAt/墓碑）已经按它需要
  的形状准备好了，`updatedAt` 的兜底口径也是为它留的。→ **M3 已做**，见
  [M3-实现说明.md](M3-实现说明.md) 第六节。
- **待办提醒未做**（`todoReminderTime` / `checkReminderTime` 只是被原样保留，不生效）；
  邮件通知同理。
- **天气未做**：`weatherEnabled` / `weatherCity` 同样是只读保留。插件在新建日记后会插一行
  天气引用，需要联网抓取，属 M4。
- **待办文字修改未做**（插件有 `updateTodoText`）；现在只能删掉重加。
- **附件目录没有与插件的 `pastedImageFolder` 统一**：M1 把附件目录放在 localStorage，
  插件放在库内配置。两边换用时这一项要手工设两次。留待后续统一——它牵扯 M1 已跑通的
  粘贴链路，不适合在 M2 里顺手改。→ **M3 已统一**到库内配置（与插件同一个键），旧本机
  设置作一次性迁移，见 [M3-实现说明.md](M3-实现说明.md) 第十节。
- **跨零点不刷新**：「今天」是渲染时算的，应用一直开着跨过零点不会自动跳到新的一天。
- **日历不能跳到指定年月**（只能逐月翻 + 「今天」）。
- **不是所有插件设置都有界面**：日记目录、日期格式、两个模板能改，其余键只保证不被抹掉。
- **W 列单击无动作**（与插件一致）——若想让单击跳到该周的周记，得改这条约定。
- **当天日记行的 `⋯` 没有"复制链接"**之类的额外项（插件也只有重命名/删除）。
- **待办列表与当天日记的最大高度是写死的**（220px），没有按窗口高度自适应；
  笔记特别多的日子会在栏内滚动。
- **`{{date:}}` 空格式串**会展开成 moment 的 `toISOString()`（moment 对空格式串的规定行为），
  与插件一致。看起来怪，但改掉就会与插件展开出不同的内容。
- **周记没有"名字"的概念**：一周一篇、名字固定为「周记」，所以 W 列双击直接创建。
  想给某周多写几篇（如周记 + 周计划）得用文件树的「＋笔记」，而它们不会被当成周记打点。
