# A2 实现说明（第一批）：移动布局骨架

> 目标：手机上从「缩小的桌面版」变成「移动应用形态」。本批交付**布局骨架与交互基础**：
> 抽屉导航、底部导航、触屏交互替换、返回键语义。Markdown 工具栏、设置面板全屏化、
> 速记管理适配属 A2 后续批次。

## 一、布局形态

**判定口径**：CSS 用 `@media (hover: none) and (pointer: coarse) and (max-width: 900px)`
（触屏 + 窄屏），React 交互用 `isMobile()`（UA）。桌面窄窗口（有鼠标）保持现有
挤压布局不变——媒体查询的三重条件保证互不误伤。

| 区域 | 桌面 | 移动端 |
|---|---|---|
| 左栏（文件树） | 常驻挤压布局 | **抽屉**：`position:fixed` 浮在内容上，底栏/顶栏按钮唤起，点遮罩或选中笔记自动收起 |
| 右栏（日历/目录/统计） | 常驻 | 同款抽屉（右侧滑出） |
| 底部 | 状态栏 | **底部导航**：文件 / 速记 / 面板 三键（`env(safe-area-inset-bottom)` 适配手势条） |
| 顶栏 | 完整（窗口控件/搜索框/仓库名/模式切换） | 精简：仓库 pill + 搜索钮 + 实时/源码 + 设置；窗口控件、置顶、专注模式、左右栏开关、brand 全部退场 |
| 状态栏 | 常驻 | 隐藏（被底栏取代） |
| ⋯ 行内菜单 | hover 显示 | **常驻**（触屏无 hover；待办行/代码块等同类交互 A2 后续批次照此办理） |
| 快捷键提示（kbd） | 显示 | 隐藏（无物理键盘） |

冷启动语义：移动端**总是从双栏收起开始**（抽屉形态；不跨会话记忆展开态——
用户上次的展开状态不应让每次打开都糊一脸抽屉）。桌面维持「记忆上次状态」。

实现上**复用现有 `leftCollapsed/rightCollapsed` 状态机**：CSS 把侧栏从挤压布局改成
浮层，React 侧只是默认值与入口按钮变了——`activateVault`/`refresh`/文件树渲染等
全链路零改动，桌面回归（verify-all 12 步）无影响。

## 二、返回键语义（原生配合）

**实测发现**：Tauri/wry 的默认返回键 = webview 历史后退，历史尽头直接退出应用——
SPA 下的表现就是「按一下返回直接杀掉应用」。

**方案**（`MainActivity.kt`）：在 `onWebViewCreate`（wry 的开放钩子）里注册自己的
`OnBackPressedCallback`，按 **dispatcher 后注册者优先** 的规则排在 wry 的 callback
之前；前端先消费：

```
back 按下 → __qnConsumeBack()：
  设置面板开着 → 关      → 消费（不退出）
  命令面板开着 → 关      → 消费
  仓库列表页   → 关      → 消费
  速记弹窗     → 关      → 消费
  左/右抽屉    → 收起    → 消费
  都没开       → 放行（isEnabled=false 触发 dispatcher → wry 的后退/退出，再自恢复）
```

**为什么不能覆写 `onBackPressed`**：wry 的 callback 以限定 `this@WryActivity.onBackPressed()`
调用——Kotlin 限定调用不走虚分发，子类覆写永远收不到（第一版实现实测落空）。
`evaluateJavascript` 异步询问前端，回调线程是 UI 线程，`super.onBackPressed()` 的
替代（dispatcher 放行）在回调里执行，安全。

模拟器自动化验证：抽屉打开 → KEYCODE_BACK → 抽屉收起且进程存活；再 KEYCODE_BACK
→ 进程退出（`SECOND_BACK_EXITED`）。

## 五、第二批：Markdown 工具栏、设置全屏化、返回键保存、长按（已交付）

> 用户确认 IME 手打测试通过（2026-10-04）——A0 的 go/no-go 门正式关闭。

- **Markdown 工具栏**（`mobile-md-toolbar`）：移动端打开笔记时浮动在编辑区与底栏
  之间，6 键：标题 H / 粗体 B / 行内代码 `</>` / 无序列表 • / 待办 ☑ / 代码块 {}。
  `onMouseDown` + preventDefault——点击不打走焦点，IME 组合不中断。
  新命令（`lib/codeEdit.ts`）：`toggleTaskList`/`taskToggleLine`（独立于 listToggleLine——
  任务框语义差异大：bullet 带框才算任务行、去框连 `-` 一起去；不动 ListKind 类型，
  渲染端零影响）、`toggleBold`/`wrapSelection`（选中包裹/取消包裹，对齐 autoPairs 语义）。
  模拟器验证：待办前缀 `- [ ] ` 与粗体 `**` 包裹均正确写入并自动保存落盘。
- **设置面板全屏化**：移动断点下 `.settings-panel` 从 `absolute + min(860px)` 改为
  `fixed inset:0` 满幅 + 顶部安全区留白（实测 412×915 = 视口满幅）。
- **返回键保存语义**：消费链最后一级——无弹层无抽屉但 `dirtyRef` 时先 `saveNow()`
  并消费该次 back（再按一次才退出；落盘异步，evaluateJavascript 的同步判定等不了）。
- **长按菜单零代码成立**：文件树/菜单全部基于 `contextmenu` 事件，Android WebView
  长按原生触发它——桌面右键菜单在触屏上自动变长按菜单。补 `user-select: none`
  （tree/tab/cm-row）防系统文本选择手柄抢交互。

## 六、第三批：Inbox 与设置面板的移动修复（用户实测反馈，已交付）

用户真机/模拟器实测反馈了三个问题，同根因 + 一处独立优化：

1. **速记管理（Inbox）布局烂、找不到返回、连带命令面板错位**——根因一条：
   桌面规则 `.app.inbox-open .editor-pane { min-width: 700px }`（「空间不足先藏
   侧栏，不压列表」）在 412px 视口上把整个 app 撑到屏外——返回钮（×）在 x≈680
   屏幕外、空状态文字被裁、fixed/absolute 浮层（命令面板）跟着错位。移动断点
   内放开（`min-width: 0`），三者一并修复。验证：返回钮 visible@367（屏内）、
   空状态两行完整、底栏保留、面板宽度 = 视口。
2. **设置面板布局**（用户测的是旧版，全屏化已在第二批交付；本批补导航优化）：
   移动断点下 `.settings-panel` 纵排改横排——`.settings-nav` 从 220px 竖列改为
   顶部横滚条（60px 高），内容区 `settings-body` 占满剩余。验证：内容右侧不越界、
   控件（下拉/复选/按钮）全部完整。
3. **截图里的绿色圆圈**：模拟器开发者选项的「显示点按操作」指示器（`show_touches`），
   非应用问题；已在模拟器上关闭（`settings put system show_touches 0` +
   `pointer_location 0`）。

桌面回归 verify-all 12 步全绿（改动全部圈在移动断点内）。

## 七、第四批：状态栏避让、快速笔记可关、设置导航收尾（用户复测反馈，已交付）

用户复测反馈三项，全部修复：

1. **应用内容遮挡系统状态栏**——根因：targetSdk 35 强制 edge-to-edge，而 Android
   WebView 里 `env(safe-area-inset-*)` 恒为 0（不可靠），WebView 自身
   `setPadding` 也不收缩网页内容（已知行为）。**可靠通道是原生 insets →
   WebView 的 layout margin**：`MainActivity.onWebViewCreate` 在 decorView 根
   （dispatch 源头，挂 WebView 上收不到）注册 `OnApplyWindowInsetsListener`，
   把 systemBars+displayCutout 转成 WebView margin。实测 viewport 从 915 缩到
   867（正好让出状态栏+手势条），顶栏/底栏全部从系统区让开。键盘（ime）刻意
   不参与——`interactive-widget=resizes-content` 已处理，双重收缩会抖。
   同时把 window 背景设为主题的 `windowBackground`——系统栏透明后透出应用
   配色而不是刺眼白色（浅色主题跟随系统，与应用内主题选择的联动排后续）。
2. **快速笔记弹窗关不掉**——两层：①「Esc 关闭」是 kbd 提示样式，手机上不像
   按钮（点击其实一直生效）——移除断点内强化成描边按钮、隐藏 kbd；②拦截层
   `menu-backdrop` 是透明的，设置面板开着时毫无浮层感——`:has(+ .quick-capture)`
   给它加深色遮罩并抬 z-index 到 940（弹窗 950 之下、面板 20 之上）。
   **返回键关错层的修复**：消费链原来是固定优先级（设置最先），设置开着时按
   返回关的是设置而用户看到的是弹窗还在——改为**视觉层级序**（弹窗 z950 >
   面板 > 仓库页 > 设置 > 抽屉），谁在最上先关谁。模拟器验证：设置+弹窗
   双开时第一次 back 关弹窗（设置保留）、第二次关设置。
3. **设置导航右上角被切**——横滚行的搜索框占近半宽度且 tab 顶到屏幕右缘。
   移动端隐藏设置搜索（`settings-search`，桌面 Ctrl+F 场景），tab 行右缘加
   渐隐 mask 提示可滑动。

桌面回归 verify-all 12 步全绿。

## 八、第五批：设置页真机复测修复（已交付）

用户真机复测反馈三项：

1. **返回手势关不掉设置页**——真机是手势导航，targetSdk 35 默认启用
   **predictive back**（系统级 `OnBackInvokedCallback`），手势路径绕开了
   androidx dispatcher 的桥接（模拟器我用三键 KEYCODE_BACK 测不出来）。
   manifest 显式 `android:enableOnBackInvokedCallback="false"` 回到传统
   back 分发，androidx callback 恢复工作。预测性返回动画的适配排后续。
2. **设置页没有关闭按钮**——上一批横排化把 `.settings-nav-head`
   （关闭钮 × 的唯一容器）`display:none` 了，× 被连带藏掉。恢复 head 行
   （标题 + 已保存 + × 独占一行），分类 tab 平铺其下。
3. **选项被「分割」**——两个独立问题叠加：
   a. `.settings-row` 的 label 是 118px 固定列，手机上长说明溢出与控件
      交错——移动端改为 label 独占一行、控件满宽；
   b. `.settings-hint` 的 `display:flex` 把说明文本的每个内联片段
      （文本/`<b>`/文本）拆成并列 flex item——窄屏下视觉上是「两列文字
      交错」（截图里的「仓附库名……件」）。移动端回归块级流、隐藏折叠钮。
   c. 分类导航从横滚改 **wrap 平铺**（两行），最后一个 tab 不再被切一半。

模拟器验收：关闭钮右上角可见（24px@right400）、导航全可见、云同步区所有行
与 hint 无越界无交错、hint 块级流生效。桌面 verify-all 12 步全绿
（改动全部圈在移动断点 + manifest back 标志）。
