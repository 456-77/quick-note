# A2 实现说明（第一批）：移动布局骨架

> 目标：手机上从「缩小的桌面版」变成「移动应用形态」。本批交付**布局骨架与交互基础**：
> 抽屉导航、底部导航、触屏交互替换、返回键语义。Markdown 工具栏、设置面板全屏化、
> 速记管理适配属 A2 后续批次。

## 一、布局形态

**判定口径**：CSS 用 `@media (hover: none) and (pointer: coarse) and (max-width: 900px)`
（触屏 + 窄屏），React 交互用 `isMobile()`（UA）。桌面窄窗口（有鼠标）保持现有
挤压布局不变——媒体查询的三重条件保证互不误伤。

| 区域 | 桌面 | 移动端 |
|---|---|---|
| 左栏（文件树） | 常驻挤压布局 | **抽屉**：`position:fixed` 浮在内容上，底栏/顶栏按钮唤起，点遮罩或选中笔记自动收起 |
| 右栏（日历/目录/统计） | 常驻 | 同款抽屉（右侧滑出） |
| 底部 | 状态栏 | **底部导航**：文件 / 速记 / 面板 三键（`env(safe-area-inset-bottom)` 适配手势条） |
| 顶栏 | 完整（窗口控件/搜索框/仓库名/模式切换） | 精简：仓库 pill + 搜索钮 + 实时/源码 + 设置；窗口控件、置顶、专注模式、左右栏开关、brand 全部退场 |
| 状态栏 | 常驻 | 隐藏（被底栏取代） |
| ⋯ 行内菜单 | hover 显示 | **常驻**（触屏无 hover；待办行/代码块等同类交互 A2 后续批次照此办理） |
| 快捷键提示（kbd） | 显示 | 隐藏（无物理键盘） |

冷启动语义：移动端**总是从双栏收起开始**（抽屉形态；不跨会话记忆展开态——
用户上次的展开状态不应让每次打开都糊一脸抽屉）。桌面维持「记忆上次状态」。

实现上**复用现有 `leftCollapsed/rightCollapsed` 状态机**：CSS 把侧栏从挤压布局改成
浮层，React 侧只是默认值与入口按钮变了——`activateVault`/`refresh`/文件树渲染等
全链路零改动，桌面回归（verify-all 12 步）无影响。

## 二、返回键语义（原生配合）

**实测发现**：Tauri/wry 的默认返回键 = webview 历史后退，历史尽头直接退出应用——
SPA 下的表现就是「按一下返回直接杀掉应用」。

**方案**（`MainActivity.kt`）：在 `onWebViewCreate`（wry 的开放钩子）里注册自己的
`OnBackPressedCallback`，按 **dispatcher 后注册者优先** 的规则排在 wry 的 callback
之前；前端先消费：

```
back 按下 → __qnConsumeBack()：
  设置面板开着 → 关      → 消费（不退出）
  命令面板开着 → 关      → 消费
  仓库列表页   → 关      → 消费
  速记弹窗     → 关      → 消费
  左/右抽屉    → 收起    → 消费
  都没开       → 放行（isEnabled=false 触发 dispatcher → wry 的后退/退出，再自恢复）
```

**为什么不能覆写 `onBackPressed`**：wry 的 callback 以限定 `this@WryActivity.onBackPressed()`
调用——Kotlin 限定调用不走虚分发，子类覆写永远收不到（第一版实现实测落空）。
`evaluateJavascript` 异步询问前端，回调线程是 UI 线程，`super.onBackPressed()` 的
替代（dispatcher 放行）在回调里执行，安全。

模拟器自动化验证：抽屉打开 → KEYCODE_BACK → 抽屉收起且进程存活；再 KEYCODE_BACK
→ 进程退出（`SECOND_BACK_EXITED`）。

## 三、改动清单

- `src/styles.css`：移动断点整段（抽屉/遮罩/底部导航/退场清单/⋯ 常驻/kbd 隐藏）
- `src/App.tsx`：冷启动默认收起（仅移动）、底部导航、抽屉遮罩、左抽屉点行自动收
  （事件委托）、顶栏移动端搜索钮、`__qnConsumeBack` 消费链、`vaultRef`
- `src-tauri/gen/android/.../MainActivity.kt`：返回键分发（见 §2）
