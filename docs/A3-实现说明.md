## 一、相册/文件导入（零原生代码）

之前调研的结论「WebView 的 file input 需要 Activity 实现 onShowFileChooser」**过时了**：
wry 0.55 的 `RustWebChromeClient` 已内建 `onShowFileChooser`（含相机权限处理与多选），
`<input type="file">` 在 Tauri Android WebView 里原生可用，选择器就是系统的 SAF UI。

实现：

- Markdown 工具栏（移动端）新增 **📷 插入图片**：点击触发隐藏的
  `<input type="file" accept="image/*" multiple>`；`File` 对象走**与桌面粘贴同一条
  附件管线**（`paste.ts` 的 `saveAndLink` 导出复用：命名 → `writeAttachment` base64
  → 光标处插入 wiki/markdown 链接，超限与失败提示齐全）。
- 顺带收益：**移动端剪贴板粘贴图片**同样经此管线（clipboardData.files），无需额外工作。

验证：工具栏 7 键（6 Markdown + 📷）、隐藏 input 在位；选图后的落盘链路与桌面共用，
由桌面既有验收覆盖。**系统选择器的真机交互（相册 UI、拍照）留给用户验证**。

## 二、系统分享接收（「分享到 Quick Note」）

- **manifest**：MainActivity 加 `ACTION_SEND text/plain` intent-filter；
- **MainActivity.kt**：`captureShare`（onCreate 冷启动 / onNewIntent 运行中）取
  `EXTRA_TEXT` 存 `pendingShareText`；`dispatchPendingShare` **轮询派发**——WebView
  就绪 ≠ React 已挂载，每 300ms 探测 `window.__qnShareReceive` 是否注册（50 次上限
  ≈ 15s，超时放弃），就绪即 `evaluateJavascript` 派发并清 pending。JSON 转义
  （`\ " \n \r \t`）在 Kotlin 侧完成。
- **前端**：`window.__qnShareReceive(text)` → 打开快速笔记弹窗并**预填文本**
  （`QuickCaptureDialog` 新增 `initialDraft` prop）；弹窗关闭时清预填，不污染
  下次手动打开。
- 验证：模拟器上 CDP 直调接收器（接收器注册 ✓、弹窗打开 ✓、预填 ✓）；Kotlin 的
  intent 捕获已编译进包，**端到端（系统分享菜单 → 本应用）留给真机**——模拟器的
  `am start ACTION_SEND` 目标解析会挂起，无法自动化。
- **图片分享**（ACTION_SEND image/*）未接：需要 content:// 读流 + 落附件目录，
  与 wry 的 chooser 通道整合后再做（排后续批次）。

## 三、应用内更新（简化版，天然可用）

移动端不编译 updater 插件（A0 决策），前端更新检查**已有优雅降级链**：
`checkViaPlugin` 抛错（插件不存在）→ 自动回退 GitHub API 比对 → 提示新版本 +
「到发布页下载」按钮（`opener` 打开浏览器）。设置 → 关于 的检查更新在移动端
**天然工作**，v1 即用此形态；「下载 APK → intent 安装」的完整闭环需要
REQUEST_INSTALL_PACKAGES + FileProvider 的原生工作，排后续批次。

## 四、内存治理（回后台超时清理）

App.tsx 的 `visibilitychange` effect 扩展：**hidden 3 分钟**后清空 mermaid SVG
缓存（`livePreview.ts` 新导出 `clearMermaidCache`；缓存是纯内存开销，几百 KB/张，
清掉后下次渲染按需重建几百毫秒）。visible 回来时取消定时器并重扫仓库（既有逻辑）。
对齐桌面「失焦 3 分钟降档」的节奏；WebView 本身的内存回收交给系统（Android 的
LMK 会处理，桌面那套 WebView2 COM 通道在 Android 上不存在也不需要）。

## 六、第二批：签名发版与 APK 应用内安装

### 6.1 发布签名

- Keystore：`H:\develop\keystore\quick-note-release.keystore`（alias `quick-note`，
  RSA 2048，有效期 30 年），**密码在同目录 `quick-note-release.txt`——必须备份进
  密码管理器，丢失后已发布的应用将永远无法更新**；
- 配置：`gen/android/app/keystore.properties`（模板 .gitignore 已忽略，不入库）
  + `build.gradle.kts` 的 `signingConfigs.release`（读 properties，**缺文件时
  release 回退 debug 签名**——开发机没配置也能出包，但发布必须配置）；
- release 构建开启 `isMinifyEnabled`（R8 混淆压缩，体积会明显小于 debug）。

### 6.2 应用内 APK 更新（完整闭环）

通道：**JS → Kotlin 桥**（`webView.addJavascriptInterface`，上行通道的首次建立；
Rust 命令到不了 Android intent）：

- `qnAndroid.canRequestInstall()` / `requestInstallPermission()`——「安装未知应用」
  一次性授权（manifest 加了 `REQUEST_INSTALL_PACKAGES`）；
- `qnAndroid.installUpdate(url)`——桥线程下载（HttpURLConnection 流式，
  filesDir/update/ 只保留本次包）→ FileProvider URI（file_paths.xml 加
  `files-path update/`）→ 主线程 ACTION_VIEW 拉起系统安装器；
- 完成经 `__qnUpdateDone(ok, message)` 回报前端。

前端：`checkForUpdate` 解析 release 的 **`.apk` 资产直链**（`UpdateInfo.apkUrl`）；
更新弹窗移动端按钮变「**下载并安装**」（`installUpdateMobile`）：桥缺失/缺 APK
资产回退发布页；未授权先跳授权页提示回来重按；下载中显示进度态。顺带修复：
移动端点桌面版「立即更新」原本静默无操作（updater 插件的 Update 对象在移动端
永远为空）。

### 6.3 验证

- 桥注入、`canRequestInstall`（模拟器未授权=false ✓）、`__qnUpdateDone` 回调通道
  全通（CDP 实测）；**下载安装闭环需要 release 有 .apk 资产 + 真机授权，留真机**；
- **签名 release 构建通过**：`app-universal-release.apk` **13MB**（debug 171MB 的
  1/13——R8 isMinifyEnabled + Rust LTO + strip 全生效），apksigner 验证证书
  CN=Quick Note ✓。坑：keystore.properties 的路径分隔符必须用**正斜杠**
  （`H:/develop/...`）——反斜杠被 Java Properties 转义吃掉后拼出
  `app\H:developkeystore...`；
- 桌面 verify-all 12 步全绿。

## 七、第三批：图片分享接收 + 发版脚本（已交付）

### 7.1 图片分享接收

- manifest 的 SEND intent-filter 扩展 image/png|jpeg|webp；
- Kotlin `captureShareImage`：`EXTRA_STREAM` 的 content:// 流拷进 **cacheDir**
  （与 Rust/前端同沙箱，前端可直接读），pending 只存**路径+mime**；
- 派发参数扩展为 `__qnShareReceive(text, imagePath?, mime?)`；
- 前端：`read_binary_file`（新 Rust 命令，任意路径二进制 base64 回传，10MB 上限，
  信任级别同 read_text_file——路径来自系统分享入口而非网页内容）→ 构造
  `CaptureImage` 传入快速笔记弹窗（`initialImages` prop），**缩略图预览、随正文
  一并落附件目录**——完全复用弹窗既有的图片管线；
- Kotlin mime 判断的 `when(intent.type)` 直接收 nullable（`when(x)` 里 null 分支
  推断报错，先 `?: return` 再 when）。

### 7.2 发版脚本 `scripts/release-android.sh`

`scripts/release-android.sh [版本号]`（缺省读 package.json）：构建签名 release
（aarch64）→ 复制命名 `QuickNote_<ver>_android_arm64.apk` 到项目根 → apksigner
验证证书 → 打印 gh 上传命令。集成进桌面发版流程（版本号四处 → tag → 桌面构建
→ gh release create）之后：跑本脚本 → `gh release upload vX.Y.Z <产物> --clobber`。

### 7.3 验证

桌面 verify-all 12 步全绿；前端分享分支（文本+路径参数 → 弹窗+预填）CDP 验证
通过；Kotlin 编译通过。真机端到端（分享菜单选图）留用户。

## 八、第四批：真机首启修复（用户真机复测反馈，已交付）

用户在真机装 release APK 反馈三个问题，全修：

1. **首启无权限引导、点「选择基础目录」无反应**——**根因：`@tauri-apps/plugin-dialog`
   的目录选择（`open({directory:true})`）不支持 Android**，SAF 目录选择在真机上
   静默失败，引导流程整体走死。重构引导为「授权 + 建议目录」两步模型：
   ①`qnAndroid.canAccessAllFiles()`（真值=主存储可写探测）+「去授权」按钮跳系统
   「所有文件访问」页（`requestAllFilesAccess`），返回时 visibilitychange 自动重探；
   ②建议目录输入框（默认 `/storage/emulated/0/Documents/QuickNote`，可改）→
   新命令 `vault_home_set_from_path`（建目录+可写探测+写指针，set_from_uri 的
   公共逻辑提取）。SAF 通道保留给桌面。
   坑：桥的 `canAccessAllFiles` 初版掺了 `canRequestPackageInstalls`（那是安装
   未知应用的检查）导致 && 恒 false——**授权探测只用探测**。
2. **底栏再次点击无法关闭**——toggle 表达式写错（`x ? false : x` 恒 false），
   改回 `!x`。
3. **同步模型**——仓库列表页卡片新增「开启同步」入口（配置了服务端地址才显示；
   已开启的显示「⟳ 同步开启」徽标）：点击 → 切到该仓库（同步状态跟仓库走）→
   启用自动同步 → 立即同步一轮 → 回列表页。进仓库后的同步操作与 PC 端一致。

模拟器全流程验收：清指针重载 → 引导页两步 → 建议目录 → 列表发现仓库；桌面
verify-all 12 步全绿。

## 九、第五批：引导第三步——云同步配置（用户反馈，已交付）

基础目录确认后不再直接进列表，先进入**可选的同步引导**：服务器地址/账号/密码
三字段 +「保存并继续」/「跳过，暂不同步」，两条路都进仓库列表。保存只写账号
三项（enabled 留待在仓库上开启——切仓库会归零游标但保留账号），列表页的
「开启同步」按钮因此解锁。已配置过账号的用户重进引导不会再看到此步
（`!syncConfigured` 条件）。

修的 bug：目录确认成功后 `home` state 未更新，step3 的渲染条件（`home !== null`）
不成立，页面落回引导——`setHome(real)` 补上。

验证：模拟器全流程（清状态 → 授权 → 目录 → 同步表单 → 保存 → 列表），磁盘
sync-state.json 确认账号三项落盘。桌面 verify-all 全绿。

## 十、第六批：多选同步 + per-vault 状态（用户反馈的同步模型落地）

用户反馈的完整模型：引导页配一次账号 → 软件里**查看所有可同步仓库并多选同步**，
而不是进设置手动指定仓库名。落地：

- **per-vault 同步状态**（Rust `sync_state_load_for/save_for`，文件
  `sync-state-<仓库名>.json`，原子写）——与当前 UI 仓库的 `sync-state.json`
  互不干扰；
- `useSync.syncVaultOnce(path)`：为指定仓库**临时构造独立 SyncEngine**跑一轮
  （不切 UI、不动全局状态；folder/待办快照不参与批量轮，打开仓库后的常规同步
  仍完整）；冲突由引擎 conflictHold 扣住（哈希不更新），打开仓库时再次弹出裁决；
- 仓库列表页「**多选同步**」：勾选卡片 →「⟳ 同步选中（N）」→ 串行逐仓跑
  （进度实时显示），**每仓 90 秒超时上限**（连不上的仓库不拖死整批，模拟器 NAT
  会静默丢 RST，TCP 超时要等满 120s）；
- 顶栏仓库 pill 移动端直达仓库列表页（之前是桌面下拉菜单）。

模拟器验收：多选 UI（勾选高亮/批量条/进度）、批量引擎错误路径；桌面 verify-all
全绿（per-vault 逻辑全部在移动端新增代码，桌面未动）。

## 十二、第八批：云端拉取入口 + 弹窗遮挡（用户复测反馈，已交付）

1. **仓库列表「没有显示所有可同步的仓库」**——列表目前只扫**本地**基础目录；
   云端枚举需要服务端新增接口（daily-sync 没有 list-vaults API）。本批落地

   仓库名与电脑端/Obsidian 一致即可。完整的「自动枚举云端仓库列表」需要

   都在抽屉（z70）之下。移动端分别抬到 85/86；顶栏搜索/设置按钮（移动端）
