# A3 实现说明（第一批）：平台集成——相册导入、系统分享、内存治理

> 接 [A2-实现说明.md](A2-实现说明.md)。A3 的目标：发第一个可日常使用的版本。
> 本批交付三项平台能力；应用内 APK 更新走简化版（见 §三），完整应用内安装排后续。

## 一、相册/文件导入（零原生代码）

之前调研的结论「WebView 的 file input 需要 Activity 实现 onShowFileChooser」**过时了**：
wry 0.55 的 `RustWebChromeClient` 已内建 `onShowFileChooser`（含相机权限处理与多选），
`<input type="file">` 在 Tauri Android WebView 里原生可用，选择器就是系统的 SAF UI。

实现：

- Markdown 工具栏（移动端）新增 **📷 插入图片**：点击触发隐藏的
  `<input type="file" accept="image/*" multiple>`；`File` 对象走**与桌面粘贴同一条
  附件管线**（`paste.ts` 的 `saveAndLink` 导出复用：命名 → `writeAttachment` base64
  → 光标处插入 wiki/markdown 链接，超限与失败提示齐全）。
- 顺带收益：**移动端剪贴板粘贴图片**同样经此管线（clipboardData.files），无需额外工作。

验证：工具栏 7 键（6 Markdown + 📷）、隐藏 input 在位；选图后的落盘链路与桌面共用，
由桌面既有验收覆盖。**系统选择器的真机交互（相册 UI、拍照）留给用户验证**。

## 二、系统分享接收（「分享到 Quick Note」）

- **manifest**：MainActivity 加 `ACTION_SEND text/plain` intent-filter；
- **MainActivity.kt**：`captureShare`（onCreate 冷启动 / onNewIntent 运行中）取
  `EXTRA_TEXT` 存 `pendingShareText`；`dispatchPendingShare` **轮询派发**——WebView
  就绪 ≠ React 已挂载，每 300ms 探测 `window.__qnShareReceive` 是否注册（50 次上限
  ≈ 15s，超时放弃），就绪即 `evaluateJavascript` 派发并清 pending。JSON 转义
  （`\ " \n \r \t`）在 Kotlin 侧完成。
- **前端**：`window.__qnShareReceive(text)` → 打开快速笔记弹窗并**预填文本**
  （`QuickCaptureDialog` 新增 `initialDraft` prop）；弹窗关闭时清预填，不污染
  下次手动打开。
- 验证：模拟器上 CDP 直调接收器（接收器注册 ✓、弹窗打开 ✓、预填 ✓）；Kotlin 的
  intent 捕获已编译进包，**端到端（系统分享菜单 → 本应用）留给真机**——模拟器的
  `am start ACTION_SEND` 目标解析会挂起，无法自动化。
- **图片分享**（ACTION_SEND image/*）未接：需要 content:// 读流 + 落附件目录，
  与 wry 的 chooser 通道整合后再做（排后续批次）。

## 三、应用内更新（简化版，天然可用）

移动端不编译 updater 插件（A0 决策），前端更新检查**已有优雅降级链**：
`checkViaPlugin` 抛错（插件不存在）→ 自动回退 GitHub API 比对 → 提示新版本 +
「到发布页下载」按钮（`opener` 打开浏览器）。设置 → 关于 的检查更新在移动端
**天然工作**，v1 即用此形态；「下载 APK → intent 安装」的完整闭环需要
REQUEST_INSTALL_PACKAGES + FileProvider 的原生工作，排后续批次。

## 四、内存治理（回后台超时清理）

App.tsx 的 `visibilitychange` effect 扩展：**hidden 3 分钟**后清空 mermaid SVG
缓存（`livePreview.ts` 新导出 `clearMermaidCache`；缓存是纯内存开销，几百 KB/张，
清掉后下次渲染按需重建几百毫秒）。visible 回来时取消定时器并重扫仓库（既有逻辑）。
对齐桌面「失焦 3 分钟降档」的节奏；WebView 本身的内存回收交给系统（Android 的
LMK 会处理，桌面那套 WebView2 COM 通道在 Android 上不存在也不需要）。
