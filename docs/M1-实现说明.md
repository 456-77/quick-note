# M1 实现说明：Live Preview 装饰层

M1 的目标是把编辑器做成 Obsidian 那种「所见即所得」的观感——缓冲区里始终是 Markdown
原文，但语法标记被藏起来、按渲染后的样式呈现。

决策前提（已由你确认）：**富文本取 Live Preview 方案；Windows 单平台**。

## 为什么是装饰层而不是富文本编辑器

同步协议用内容 SHA-256 判增量，所以「保存时必须字节无损」。装饰层方案里文档缓冲区
**就是** `.md` 原文，装饰只影响显示、不碰内容；而 ProseMirror/TipTap 那一类富文本编辑器
是把文档解析成自己的模型再序列化回 Markdown，必然引入规范化改写。这一条决定了方案。

## 实现结构

```
src/lib/livePreview.ts
  buildLivePreviewDecorations(state, from, to)   ← 纯函数，不依赖 EditorView
  livePreviewExtension()                          ← ViewPlugin 包装
```

拆成纯函数是刻意的：装饰计算是这套方案里最容易出错的部分，纯函数可以直接在 Node 里
断言（`scripts/verify-livepreview.mjs`，43 项断言），不必启动 GUI。

装饰只做三件事：

| 手段 | 用途 | 例子 |
|---|---|---|
| `Decoration.replace`（无 widget） | 藏掉语法标记 | `**`、`# `、`` ` ``、`](url)`、`-` |
| `Decoration.mark` / `Decoration.line` | 加样式 | `cm-lp-strong`、`cm-lp-h1`、`cm-lp-codeblock` |
| `Decoration.replace`（带 widget） | 换成控件 | 复选框、圆点、`<hr>`、语言标签、图片占位 |

**节点名不是猜的**，来自 `node scripts/dump-markdown-tree.mjs` 的实际输出。几个容易记错的：
`InlineCode`（不是 `Code`）、行内标记统一叫 `*Mark`（`EmphasisMark`/`StrikethroughMark`/`CodeMark`）、
任务列表是 `Task` + `TaskMarker`、**`Image` 的 alt 文字没有子节点**（夹在两个 `LinkMark` 之间）。

### 光标所在行显示源码

`isActive(ctx, from, to)` 取选区覆盖的行号集合，节点与之相交就整体退回源码——既隐藏标记，
也**不加样式**，并跳过小部件替换。这样在源码态不会出现「看着是 `**粗体**`、却已经渲染成粗体」
的自相矛盾显示。

## 实测踩到的三个 CM6 插件约束

前两个只有跑起真实应用才能发现：违反后装饰集整体抛异常，**编辑器渲染成空白**，错误只以
界面提示条的形式出现，很容易误判成「前端没加载」。因此 GUI 测试的第一条断言就是「界面无报错」。

| 约束 | 报错 | 触发写法 | 修法 |
|---|---|---|---|
| 插件不能产生块级装饰 | `Block decorations may not be specified via plugins` | 给 `<hr>` 用 `Decoration.replace({block: true})` | 只替换 `---` 本身，保留行尾换行 |
| 插件不能替换换行符 | `Decorations that replace line breaks may not be specified via plugins` | 为消除空行而隐藏围栏后的 `\n` | 不隐藏换行符 |
| replace 装饰不能重叠 | 抛异常 | 嵌套语法下手工构造的区间可能相交 | 按起点排序后丢弃被包含的区间 |

第三条是预先加的防御（`buildLivePreviewDecorations` 末尾的重叠过滤）：装饰插件抛异常会让
整个编辑器不可用，宁可少画一点也不能崩。

**若要真正消除代码块围栏残留的近空行**，得把装饰改由 `StateField` 提供（StateField 允许
块级装饰）。代价是拿不到 `view.viewport`，装饰要按全文档计算——对几万行的笔记会有性能压力。
当前实现优先保证「视口内计算」这一性能特性，把这点美观代价记在待办里。

### 一个被单元测试抓到的真 bug

行内标记的处理最初把 `marks.push(...)` 写在了 `isActive` 判断之外，结果是：光标停在
`**粗体**` 那一行、`**` 已经显示出来，文字却仍是粗体。单元测试断言「本行不应有
`cm-lp-strong`」直接抓住了它。链接分支有同样的问题，一并修掉。

### 第二个 bug，以及"断言强度"的教训

表格单元格的行内解析里，跳过语法标记时忘了推进游标 `pos`：

```ts
if (child.name.endsWith("Mark")) continue;   // 错：pos 没动
...
if (pos < parent.to) push(doc.sliceString(pos, parent.to));  // 于是把整段（含 `**`）推了出去
```

结果是单元格里直接显示 `**粗体**`。

**单元测试当时是通过的**——因为它只断言了 `run.bold === true`（恰好为真：标记被算进
了那段"加粗"文本），没断言文字内容。GUI 测试断言 `textContent` 才暴露出来。

教训：**断言样式标记的同时必须断言文字里不含原始标记**。现在两者都有，并且加了一条
兜底断言：所有单元格的文本段都不含 `*`、`` ` ``、`~` 任一符号。

## 表格渲染

表格无法用插件渲染——整块替换多行需要块级装饰，而 CM6 禁止插件产生块级装饰。所以表格
的装饰改由 **StateField** 提供（`tableBlockField`），行内装饰仍留在 ViewPlugin 里，
两者由 CM6 自动合并。

- 单元格内容**解析行内语法后渲染**（粗体/斜体/删除线/行内代码/链接），不是原文照搬。
  做法是把单元格内容拍平成「带样式标记的文本段」（`TextRun`），好处是 widget 的 `eq`
  只需比较 JSON，DOM 构建也只按标记包一层元素，不必处理 DOM 树比较。
- **点击表格即切回源码编辑**：widget 的 `mousedown` 把光标放进表格范围，StateField 检测到
  选区落在表格内就不再替换，表格变回可编辑的 Markdown；光标移出又渲染回表格。这与
  「光标所在行显示源码」是同一条规则，行为一致。
- 列对齐从分隔行（`:---` / `:---:` / `---:`）解析。
- 表格被替换时，行内插件**跳过 Table 的子节点**：被替换的内容本来就不渲染，若仍在其内部
  产生装饰，会与块级替换区间重叠，CM6 会直接抛异常、编辑器整体空白。

代价：StateField 拿不到 `view.viewport`，表格扫描只能按全文档进行。好在只遍历语法树找
`Table` 节点，且 CM6 的语法树是增量维护的，`ensureSyntaxTree` 在树已完整时立即返回，
常态开销是遍历节点而不是重新解析。**但 StateField 的 `update` 会在每次事务（含纯选区
移动）重算**，大文档下的开销尚未实测，记在待办里。

## 模式切换

用 `Compartment` 重配置，而不是重建状态——撤销历史和光标位置都能保留。
目前提供 **Live Preview / 源码** 两档。阅读视图暂未实现（见待办）。

`ViewMode` 存在 localStorage，切换文件时沿用。

## 可测试性带来的一个编码约束

测试脚本用 Node 的类型擦除（`--experimental-strip-types`）直接加载 `src/lib/*.ts`，
因此这些文件必须是**可擦除语法**：不能用 `constructor(readonly x: T)` 这类参数属性
（它需要生成赋值代码，不是纯类型擦除）。已经在 `tsconfig.json` 打开 `erasableSyntaxOnly`，
类型检查阶段就会拦住违规写法——这是踩过一次（装饰层加载失败）之后加的护栏。

## 验证

```bash
./scripts/verify-all.sh    # 逻辑层，含装饰层 43 项断言
./scripts/verify-gui.sh    # 界面层，含 Live Preview 的真实 DOM 断言与交互
```

两层都必须有，且分工明确：

| 层 | 能验证 | 验证不了 |
|---|---|---|
| 单元（Node，纯函数） | 装饰算得对不对：藏了哪些区间、加了哪些类、小部件参数 | CM6 的运行时限制、DOM 呈现、事件是否可用 |
| GUI（CDP 读真实 DOM + 真实鼠标键盘） | 渲染结果、模式切换、点击复选框写回源码、滚动后重建 | 无法定位到具体代码行 |

「块级装饰」和「替换换行符」两个 bug 单元测试全都测不出来，是 GUI 层抓到的；
而「加粗样式没随光标回退」反过来只有单元层能精确断言。**缺任何一层都会漏。**

GUI 断言用的技巧：被隐藏的语法标记**完全不在 DOM 里**（CM6 用零宽 widget 替换），
所以直接对 `textContent` 断言「不含 `**粗体**`」即可，不需要判断可见性。

## 内存影响

打开一篇带各类语法的笔记、装饰生效时（私有工作集，即物理内存中真正属于本应用的部分）：

| 状态 | 私有工作集 |
|---|---|
| M0（无 Live Preview） | 99.5 MB |
| M1（Live Preview + 表格） | 104.6 MB |
| M1 + Mermaid 渲染出图 | 114.6 ~ 121 MB |

Mermaid 加载并渲染图表后约 +10~16MB。对应的是 832KB 的按需 chunk，这个代价可接受，
也说明**按需加载确实有效**——不含 mermaid 块的文档完全不承担这份开销。

> 测量踩坑：`measure-rss.ps1` 原先按进程名取根，机器上同时存在两个实例时会把两棵树
> 加在一起（实测得到 15 个进程、358MB 的虚高数字）。现在脚本只测最新实例，并可用
> `-ProcessId` 指定。

## Mermaid（流程图等）渲染

围栏块标注为 `mermaid` 时渲染成图。同样受"插件不能产生块级装饰"的限制（一个图是多行，
必须整块替换），所以和表格一起由 `blockWidgetsField` 处理，**共用一次语法树遍历**。

### 按需加载

mermaid 是个很重的库（含全部图表类型）。做法是在函数内部 `import("mermaid")`，让打包器
把它切成独立 chunk——只有文档里真的出现 mermaid 块时才加载，不进主包、不影响启动。
加载后常驻内存（不重复加载），另外对已渲染的 SVG 做了一个上限 30 条的缓存，避免同一张图
反复解析渲染（简单先进先出淘汰，不是 LRU）。

### 异步渲染

mermaid 的渲染是异步的，而 widget 的 `toDOM()` 是同步的，所以先放"图表渲染中…"占位，
拿到 SVG 后再填充。**渲染失败不能让编辑器崩掉**：错误信息显示在占位框里（保留源码可编辑），
测试里专门用一段故意写错的图定义覆盖了这条路径。

配置上必须用 `securityLevel: "strict"`——它会清洗标签里的 HTML 与事件处理器。
**绝不能用 `loose`**：笔记内容可能来自同步，loose 等于开注入口子。

### 为什么用 mermaid 11 而不是 12

`npm audit` 显示 mermaid 12 经 `chevrotain` 引入 `lodash-es` 的**两个 high 级漏洞**
（`_.template` 代码注入、原型污染），且没有可用的 override（漏洞范围覆盖全部已发布版本）。
换到 mermaid 11.17.2 后只剩一个，`npm audit fix` 把 `lodash-es` 升到 4.18.1 即**归零**。

用法只涉及 `initialize` + `render`，两个大版本没有差异，所以这个降级无痛。**升级 mermaid
前请先跑 `npm audit`**。

## 文件监听与外部改动

Obsidian、同步进程或别的编辑器改了库里的文件，Quick Note 要能跟上，且不能静默覆盖用户
正在编辑的内容。实现分两侧：

**Rust**（`src-tauri/src/watch.rs`）用 `notify` 递归监听仓库，做 **250ms 去抖**后通过
`vault-changed` 事件把**仓库相对路径列表**发给前端。过滤掉隐藏路径（`.` 开头的段）与非
`.md`/`.json` 文件。前端不轮询目录——轮询既费电，在大仓库上还会抖动。

**前端**（`App.tsx`）收到事件后按内容哈希判断：

| 情况 | 处理 |
|---|---|
| 路径不是当前打开的笔记 | 只刷新文件树（300ms 合并） |
| 哈希与当前一致 | **忽略**——这是自己刚保存产生的回声 |
| 哈希不同且**没有**未保存编辑 | 直接采纳磁盘版本，并尽量保住光标位置 |
| 哈希不同且**有**未保存编辑 | 弹冲突提示，提供「加载磁盘版本 / 保留我的编辑」两个选择 |

**「按哈希区分回声」是关键**：自己保存后监听器也会收到事件，不区分就会把自己的写入当成
外部改动，来回刷新甚至打架。所以保存成功后会把新哈希写回 `current`，后续事件因哈希相同而
被忽略。

采纳磁盘版本时会重建编辑器状态（换行符风格可能变了，必须随状态重建），重建后把光标
钳到原位置，避免跳回文首。

> 测试这个路径有个时序陷阱：自动保存防抖是 1.2 秒，若"先输入、再改文件"，自动保存会先
> 把冲突冲掉。`gui-external-change.mjs` 的做法是**持续小幅输入让防抖不断重置**，让编辑器
> 稳定处于"有未保存编辑"状态，冲突才可复现。

## 图片真实渲染

图片以前只是占位标签，现在真的加载库内文件。两个必要步骤：

1. `tauri.conf.json` 开启 `app.security.assetProtocol`；
2. 每次打开仓库调用 `allow_asset_dir`，把该目录加入 asset 白名单（白名单是运行时的、不持久化）。

路径解析（`resolveResource`）刻意只做**纯字符串运算**，不生成 asset URL：`convertFileSrc`
依赖 `window`，在 Node 里跑不了，而这段逻辑需要能被单元测试直接断言。解析规则：

- `http(s):` / `data:` / `blob:` / `asset:` 原样透传；
- 以 `/` 开头按仓库根解析，否则**相对笔记所在目录**（与 Obsidian 一致）；
- 逐段消解 `.` 与 `..`，且 **`..` 不允许越过仓库根**——路径永远落在库内
  （asset 白名单是第二道防线，但解析本身就该夹住）；
- URL 编码（`%20` 等）会先解码。

asset URL 只在 `toDOM()` 里生成。文件缺失或目录未授权时 `error` 事件把它降级成标签。

**踩到的坑**：降级最初写成 `img.replaceWith(chip)`，直接替换了 widget 的**根节点**，
而 CM6 正持有该节点的引用，导致 DOM 记账失效、降级标签根本不出现。现在根节点固定为容器，
只替换其子节点。

## 代码块空行

围栏被隐藏后，收尾围栏那一行就成了空行。现在给该行加 `cm-lp-fence` 类，用
`font-size: 0; line-height: 0` 压掉高度。只处理收尾行——起始行还有语言标签需要正常高度。
（起始行仍占一行显示语言标签，这是当前实现与 Obsidian 的差异。）

## Obsidian wiki 语法（`[[...]]` / `![[...]]`）

**这是最初图片"加载不出来"的真正原因。** Obsidian 默认写入的是 wiki 语法而不是标准
Markdown：粘贴图片得到的是 `![[Pasted image 20260914142803.png]]`，而我只实现了
`![alt](path)`。

更麻烦的是解析器对它的处理。lezer 的 GFM 解析器不认识 `[[...]]`，它会**硬套**成
内联链接，于是：

```
![[x.png]]   →   Image[ LinkMark "![", Link "[x.png]", LinkMark "]" ]
```

得到一个**目标为空**的 Image 节点。我的旧代码据此渲染出占位标签，内容是
`🖼 [x.png]`——方括号来自被拆开的语法。这就是截图里看到的
`🖼 [Pasted image 20260914142803.png]`。

所以 wiki 语法必须自己用正则找（`findWikiSyntax`），并且**屏蔽解析器为它生成的
Image/Link 节点**，否则两套逻辑会重复处理同一段文本。行内代码与代码块里的
`[[...]]` 不算语法。

支持范围：

| 写法 | 处理 |
|---|---|
| `![[图.png]]` | 渲染成图片 |
| `![[图.png\|200]]` | 数字识别为**宽度**（像素） |
| `![[图.png\|说明]]` | 文字识别为 **alt** |
| `![[某笔记]]` | 把目标笔记的内容**渲染进来**（内容嵌入，见下节） |
| `[[笔记]]` / `[[笔记\|别名]]` | 只隐藏方括号，文字保留为可编辑文本 |
| `[[笔记#小节]]` | 嵌入标签显示为 `笔记 › 小节` |

**解析方式与 Markdown 语法不同**：wiki 目标是**按文件名在全库查找**的，不是相对路径。
所以在打开仓库时建立一份「小写文件名 → 相对路径」索引（`.md` 额外注册去掉扩展名的键），
同名时取路径最短的（近似 Obsidian 的"离当前笔记最近"）。含 `/` 的写法仍按路径解析；
索引里找不到时退回相对笔记目录，不会崩。

索引是**就地更新**的同一个 Map 实例——编辑器状态的 facet 里持有的是这个引用，换成新实例
不会生效。索引刷新后通过 `refreshDecorations` 这个 StateEffect 通知编辑器重算装饰
（装饰只在文档/选区/视口变化时重算，索引变化不在其中）。

## 内容嵌入（transclusion）

`![[某笔记]]` 会把目标笔记的内容渲染进来。三种形式：

| 写法 | 嵌入范围 |
|---|---|
| `![[某笔记]]` | 整篇 |
| `![[某笔记#小节名]]` | 该标题小节（取到下一个**同级或更高级**标题之前；更深的子标题不截断） |
| `![[某笔记#^块标识]]` | 含 `^块标识` 的整个段落 |

### 安全前提（不要改动）

嵌入的内容可能来自同步，也就是**外部来源**，而这个应用具备写文件能力。因此：

- markdown-it 必须用 **`html: false`**——把笔记里的原始 HTML 转义掉而不是渲染。
  **不要为了"更贴近 Obsidian"而打开 html。** markdown-it 默认还会拦掉 `javascript:`
  之类的链接协议。
- 链接一律渲染成**不可导航的 span**：Tauri 的 webview 里点一个 `<a href>` 会把整个应用
  导航走，那是很难恢复的状态。

代价是：嵌入内容里的原始 HTML 会显示成文本（Obsidian 会渲染它）。这是有意的取舍。

### 分层

`sliceSection` / `prepareEmbedMarkdown` / `splitEmbedTarget` 是**纯函数**，在 Node 里直接
断言（`verify-livepreview.mjs` 场景 I）。只有最终渲染依赖浏览器环境（markdown-it 与
`convertFileSrc`）。`prepareEmbedMarkdown` 把嵌入内容里的 wiki 语法转成 Markdown：

- `![[图.png]]` → `![alt](<wiki:图.png>)`（用 `<>` 包住以容忍文件名里的空格；宽度放在
  alt 里——纯数字即宽度，避免往 URL 塞参数）
- `![[某笔记]]` → `[[📄 笔记]](<wiki-link:...>)`：**嵌套嵌入不递归展开**
- `[[笔记|别名]]` → `[[别名]](<wiki-link:笔记>)`

### 刷新与缓存

渲染结果按 `${generation}:${相对路径}#${小节}` 缓存。代际在每次刷新时 +1，一处变化同时做到
三件事：缓存失效、widget 的 `eq` 判定为"不等"从而重建 DOM、装饰重算。

**上下文必须是同一个可变对象**：facet 在编辑器状态创建时就捕获了引用，之后更新仓库路径 /
文件索引 / 代际只能就地改字段，换成新对象不会生效。

### 模块分层

为了写内容嵌入，把路径解析抽到了 `src/lib/paths.ts`：`livePreview` 需要调用 `embed` 的渲染，
而 `embed` 需要 `paths` 的解析，三者若混在两个文件里会形成循环依赖。现在的层次是
`paths` → `embed` → `livePreview` → `editor` → `App`。

另外 `embed.ts` 直接调 `invoke("read_note")` 而不是 import `api.ts`——避免把 dialog 插件
拖进 Node 测试的加载路径。

### 这次自己踩的坑

重构 `absoluteInVault` 时忘了**先拆开仓库路径的路径段**，结果拼出
`H:/vault//pic.png` 这种带双斜杠的路径。单元测试里本来就有一条"反斜杠与结尾斜杠被规范化"
的断言，直接把它抓住了——**已有的边界断言是有价值的**，别在重构时顺手删。

## 附件粘贴

把剪贴板里的图片/文件写进仓库的附件目录，并在光标处插入链接。**只在剪贴板里真的有文件时
才接管粘贴**——纯文本粘贴保持编辑器默认行为，这一点很重要，否则会破坏最日常的操作。

### 命名与防覆盖

图片一律命名为 `Pasted image <时间戳>.<扩展名>`，与 Obsidian 一致：用户库里已经全是这种
名字，新文件会和它们排在一起。其他文件（zip、pdf）保留原文件名，只做字符清洗。

重名时 Rust 侧自动加序号（`a.png` → `a 1.png` → `a 2.png`），**绝不覆盖已有文件**——
粘贴属于"新增"，静默覆盖用户的文件是不可接受的。

### 路径安全（两道）

- 文件名在 JS 侧清洗：去掉路径分隔符、Windows 禁用字符、控制字符，并去掉开头的点；
- Rust 侧**再校验一次**：拒绝含 `/`、`\`、以点开头、含非法字符的名字；附件目录走与笔记
  相同的路径校验（拒绝隐藏目录、拒绝越界）。

两侧都做是有意的：JS 侧负责生成合理的名字，Rust 侧是安全边界。单元测试里有一条
`../../逃逸` 的用例，验证结果里既不含分隔符也不以点开头。

### 链接写法

默认 **wiki**（`![[图.png]]`）——用户库里用的就是 wikilink。可切到 markdown，此时写
**仓库根相对路径**（`![图.png](/attachments/图.png)`）：相对笔记目录的写法在笔记位于
子目录时很容易指错。

### 二进制的传法

附件走 **base64**，不是 JSON 数字数组：同样内容体积约为后者的 1/3，编码解码也快得多。
两侧都有 64MB 上限，挡住误操作。

### 设置为什么是模块级可变对象

粘贴处理发生在 CodeMirror 的事件回调里，拿不到 React 的 props。所以设置放在
`settings.ts` 的模块级对象里（localStorage 持久化 + 订阅通知），扩展通过**读实时值的
函数**访问它——用快照的话，改设置要重开文件才生效。

### 测试的一个取舍

GUI 测试用**合成的 ClipboardEvent + DataTransfer**（内含一个真实 PNG）注入粘贴，而不是去
设置系统剪贴板——那会侵入你的环境。因此未覆盖的部分仅限于"浏览器如何填充剪贴板数据"，
而读取、编码、写盘、命名、插链接、自动保存都是真的。

> 顺带一个测试教训：React 的重渲染是异步的。测试辅助函数不能在同一个同步表达式里
> "点按钮 → 立刻查面板"，必须分步并等待一拍。

## 新建笔记与文件夹

侧栏顶部的「＋笔记 / ＋文件夹」展开一行名称输入，Enter 确认、Esc 取消。

- 名称缺 `.md` 会自动补；名称里可以写 `子目录/名称`，中间目录自动创建；
- **重名自动加序号，绝不覆盖已有文件**（与附件粘贴同一套逻辑，共用 `unique_path`）；
- 隐藏名（点开头）、非法字符、`..` 越界都会被拒绝并给出提示，**输入行保持展开**方便改名重试；
- 新建笔记后立刻打开它，省掉再去树里找一次。

### 目标目录是"当前打开笔记所在目录"

树里没有"选中文件夹"的概念，所以新建的落点取**当前打开笔记所在目录**（没打开笔记则放仓库根），
输入行的提示里会明确写出落点，不会让人猜。

有一个副作用要知道：新建的笔记会被立刻打开，因此目标目录会**跟着下沉**——在 `日记/` 下新建
`子目录/笔记` 之后，下一次新建的落点就变成 `日记/子目录/`。这是"新笔记放在当前笔记旁边"这一
约定的自然结果，提示里也能看到；如果更希望"固定落在某个目录"或"按树里选中的文件夹"，那需要给
文件树加上选中态。

### 测试用独立临时仓库

新建功能的 Rust 测试**不碰 `test-vault/`**，而是在系统临时目录里另建一个仓库。原因：往 fixture
里塞文件会让字节精确基线的比对失败，而那条基线同时也在守护测试流程本身。

## 文件树：显示仓库的真实结构

**这一节记录一个被用户报上来的 bug**：新建了文件夹，资源管理器里能看到，软件里看不到；
往里放一个 `.md` 文件后又能看到了。

根因很直接：文件树是从**md 文件列表**反推目录的。空目录不产生任何 md 路径，于是树里根本
没有这个节点。`list_notes` 只返回 `.md` 文件，是设计上的疏漏。

修法：Rust 侧一个 `list_entries` 返回**目录（含空目录）与所有文件**，前端一份数据同时做三件事
——渲染文件树、建立 wiki 语法的文件名索引、统计笔记数量（目录与非 md 不计入）。

顺带两个相关调整：

- **非 Markdown 文件也列出**，但不可编辑（灰色、无点击反馈、title 里说明）。文件树要忠实反映
  仓库结构，否则"这个文件夹里到底有什么"永远看不出来。
- **不含笔记的目录默认收起**。作者本人的仓库里 `image/` 下有 146 个附件，若默认展开会把侧栏
  刷满与笔记无关的条目。判断依据是"子树里有没有笔记"。

另外把 `watch.rs` 的扩展名过滤去掉了：**空目录的新建/删除不产生任何 `.md` 事件**，按扩展名
过滤就永远不会通知前端——这也是同一个 bug 的另一半（在资源管理器里新建目录，软件不会刷新）。
现在只排除隐藏路径，其余变化一律通知，具体要不要重载交给前端判断。

**教训比 bug 本身更值得记**：新建功能的 GUI 测试当时断言了"文件夹在磁盘上存在"，但**没有断言
它在界面上可见**。磁盘对了、界面错了，测试照样全绿。现在这条"空文件夹必须出现在文件树里"
是明确的回归断言。

## 文件管理：新建 / 重命名 / 删除

入口是右键菜单（重命名 / 删除）。三条约束是刻意的：

### 重命名必须同步更新引用

wiki 语法**按文件名解析**（`[[笔记]]` 不写路径），所以改名会让所有引用静默失效。Rust 侧扫一遍
全库笔记，改写 `[[旧名]]`、`![[旧名]]`、`[[旧名|别名]]`、`[[旧名#小节]]` 这些写法，返回改动了
哪些笔记，界面会显示"更新了 N 篇笔记里的引用"。

**Markdown 相对路径链接不动**——那是路径不是名字，改名后怎么处理应当由用户决定。

### 重命名不覆盖、不加序号

目标名已存在时报错，让用户知道。新建重名会自动加序号（`a 1.md`），但重命名是"改名"：名字被
占用却静默变成另一个名字，会让人以为改成功了。

**被改名的条目（或它所在的目录）如果正开着，编辑器要跟着换到新路径**。否则下一次自动保存会
按旧路径写回去，把刚改的名"改回来"。

### 删除进仓库内的 `.trash`，不是直接抹掉

误删笔记是不可逆的损失，先保证能找回是底线。`.trash` 是隐藏目录，枚举时被跳过，所以它不会出现
在文件树、wiki 索引或同步范围里——不需要额外处理。

（Obsidian 允许选"移到系统回收站"，那需要平台 API（如 `trash` crate），暂未提供。）

**删除的正好是当前笔记时，编辑器会关闭**。理由和重命名那条一样：不关的话，排队中的自动保存
会把文件重新写回来。GUI 测试里有一条专门的断言——删除后等待 2 秒，确认文件没有被写回来。

## 主题与设计变量

所有颜色都收敛到 `src/styles.css` 顶部的一组 CSS 变量（语义命名：`--bg`、`--panel`、
`--surface-2`、`--text-dim`、`--syn-keyword`…），深色主题只覆盖这一组。

**新增样式时不要写死色值**——写死的那些在深色主题下会漏掉。改造时就是从这条入手的：
把原本散落的 `#fafbfd`、`#fbfbfc`、`#f0c0c0`、两处 `box-shadow` 全部换成了变量。

### 「跟随系统」在 JS 里解析，不在 CSS 里

`lib/theme.ts` 把模式解析成具体的 `light`/`dark` 写到 `<html data-theme>`。
这样深色色板在 CSS 里只写一份。

如果改用 `@media (prefers-color-scheme: dark)`，就得把整套深色变量再抄一遍——
而"同一份逻辑写两遍"在这个项目里已经踩过坑（`sync.ts` 的哈希口径、测试里复刻的换行符探测
都栽在这上面）。系统主题变化时用 `matchMedia` 的 change 事件重新解析。

`main.tsx` 在渲染前就先应用主题，否则深色模式用户会看到一瞬白底闪烁。

### 编辑器配色：变量 vs 需要重配的部分

- **语法高亮走 CSS 变量**（`lib/syntaxTheme.ts` 的 HighlightStyle 用 `var(--syn-*)`），
  所以切主题**不需要重建编辑器状态**。覆盖的标签是 CM6 内置 `defaultHighlightStyle` 的
  超集——内置那份用的是写死的浅色（`#708`、`#a11`…），深色下会花掉。
- **明暗标记必须重配**：CM6 靠 `EditorView.darkTheme` 决定光标、选区等内置配色的明暗，
  这个 facet 只能通过 Compartment 重配置（`applyDarkTheme`）。
- 活动行与选区的底色用 `!important` 压过 CM6 内置的固定色（见 `styles.css`）。

GUI 测试里有一条断言专门验证"高亮色等于色板里的值"：浅色 `rgb(130, 80, 223)`、
深色 `rgb(199, 146, 234)`——两者都断言，才能证明内置的默认高亮确实被替换了，
而不是碰巧颜色相同。

## 额外语法：公式 / 高亮 / 注释 / 手写 HTML / 链接 / callout / 标签

按作者仓库的实际用法逐项挑的（101 篇笔记的统计）：

| 语法 | 出现于 | 处理 | 备注 |
|---|---|---|---|
| 围栏代码块 | 64% | 高亮 + 语言标签 | |
| 块引用 / 表格 / 分隔线 | 44~51% | 已支持 | |
| wiki 嵌入 | 29% | 已支持 | |
| **裸链接 `https://…`** | **38%** | **当链接渲染** | 最大的一处缺口：之前 403 处完全是纯文本 |
| 行内公式 `$…$` | 21% | KaTeX 渲染 | 懒加载，连字体一起 |
| 手写 HTML | 18%※ | 清洗后渲染 | ※初版统计被代码块里的 `<Route>`/`<dependency>` 干扰，实际是行内 `<font>`/`<br/>` 为主 |
| 高亮 `==…==` | 13% | 藏 `==` + 加底色 | |
| 标签 `#tag` | 7% | 加标签样式 | 点击跳转未实现 |
| callout `> [!note]` | 3% | 容器样式 + 图标标签 | |
| setext 标题 | 2% | 同 ATX 标题 | `=====` 行要压掉高度 |
| 多行注释 | 2% | **未做** | 需要块级装饰，见待办 |

| YAML frontmatter | 0% | **不做** | 你的库一篇都没有——这也是先量一遍的价值 |

### 三条踩过坑的规则

**1. 标签的判定是"前一个字符不能是字母数字"，不是"必须是空白"。**
第一版写成"`#` 前面是行首或空白"，结果 `正文、#标签` 里的标签识别不出来（中文顿号不是空白）。
是测试里那条 `#嵌套/标签` 的断言把它逼出来的——如果只测英文语境就漏了。放宽成
`(?<![\p{L}\p{N}_])` 之后，`[[笔记#小节]]`（前面是汉字）仍然正确地不算标签。

**2. setext 标题的下划线独占一行。**
`HeaderMark` 在**第二行**，而标题文字在**第一行**（与 ATX 相反）。藏掉 `=====` 之后那一行会
变成空行，所以要给行加折叠类压掉高度——与代码围栏同一套处理（`cm-lp-collapsed`）。

**3. 扫描要按顺序排除已接管的区间。**
`<font color="#c00">` 里的 `#c00` 被标签扫描器当成了标签。虽然它随后被 HTML widget 替换、
并不会显示出来，但装饰集应该保持干净。现在扫描顺序是
**HTML → wiki → 公式/高亮/注释/标签**，后面几个会拿到前面已接管的区间作为排除项
（`taken`），所以属性值里的 `$`、`#` 都不会被误判。

### 外部链接：Ctrl/Cmd+点击用系统浏览器打开

- 只认 `http`/`https`，其他协议（`file:`、`javascript:`…）一律不开。
- 用**修饰键**而不是直接点击：直接点击要留给"把光标放到这里"，误触跳走浏览器很难受
  （Obsidian 也是修饰键）。
- 链接是 mark 装饰（不是 widget），DOM 上只有个 span、拿不到 URL，所以从点击位置
  **反查语法树**找最近的 `URL` / `Link` 节点（`externalUrlAt`，纯函数、可单测）。
- 链接 span 上带 `title` 提示，"Ctrl+点击"这个用法才可能被发现。

## 清洗只作用于显示——**不影响同步**

这是作者专门问过的问题，也是实现时最重要的一条约束：

> DOMPurify 只清洗**要塞进 widget 的那段 HTML**。文档缓冲区、编辑器状态、磁盘文件
> 始终是原文。所以同步看到的内容哈希不变，不会产生虚假改动或冲突。

实现上没有"清洗后回写"这条路径：`sanitizeHtml` 的返回值只赋给 `container.innerHTML`。
这个不变量由 `verify-all.sh` 末尾的**字节精确基线**守着——真要有人加了回写，
基线比对会立刻失败。

（顺带说明：同一原则也适用于 mermaid/KaTeX，它们都只替换显示。）

### 允许清单里的几个刻意取舍

- **不允许 `style`**：内联样式能覆盖界面（`position:fixed` 盖住整个应用），
  或用 `url()` 把数据带出去。
- **不允许 `class` / `id`**：用户 HTML 里写 `class="settings-panel"` 会套上应用样式。
- **链接一律降级成 span**：Tauri 的 webview 里点 `<a href>` 会把整个应用导航走。
- **禁止 `script`/`style`/`iframe`/`form` 与所有内联事件属性**。
- **失败兜底**：`sanitizeHtml` 在环境不支持清洗时返回 `null`，调用方退化成显示源码
  （`is-raw` 样式）。**宁可显示源码，也绝不注入未清洗的 HTML。**
- KaTeX 用 `trust: false`，禁掉 `\href` 之类的可信命令。

## 从这次漏测得到的教训

**用目标用户真实的内容做验收，而不是自己构造的"标准"样例。** 我的 fixture 一直用
`![alt](attachments/pic.png)`，测试全绿，但真实仓库里一处都不是这种写法——Obsidian 默认
就是 wiki 语法。单元测试和 GUI 测试都覆盖了"标准语法"，却整体漏掉了真实场景。

现在 fixture 里同时包含两种语法，wiki 语法的三种写法（裸写 / 带宽度 / 带说明）、笔记嵌入、
以及"行内代码里不当语法"都有断言。

## 待办与遗留

- **多行注释 `%%…%%` 未隐藏**：跨行替换换行符是插件不允许的，要走 StateField 的块级装饰。
  只处理单行的原因在此。
- **callout 未做可折叠**：Obsidian 点标题能折叠，这里只做了样式与图标。
- **标签不能点击**：只加了样式（点击筛选/跳转需要全库标签索引与路由）。
- **脚注未渲染**：需要收集定义并生成脚注区，属独立功能。
- **块公式 `$$…$$` 未支持**，YAML frontmatter 也未处理（作者仓库里都没用到）。
- **没有"移到系统回收站"选项**：删除固定进仓库内的 `.trash`（可改回，但需要平台 API）。
- **重命名不支持移动位置**：只改名称；也不能在重命名时同时改所在目录。
- **重命名不更新 Markdown 相对路径链接**（只更新 wiki 引用，理由见上）。
- **非 Markdown 文件不可打开**：列在树里只是为了反映结构，点击没有动作
  （想用系统程序打开需要接 opener 插件的能力，未做）。
- **嵌套嵌入不展开**：嵌入内容里的 `![[另一篇笔记]]` 显示成占位链接，不会再嵌一层。
  要支持多层需要把渲染改成递归并加深度上限。
- **嵌入内容里的原始 HTML 被转义显示**（安全取舍，见上）。
- **`#小节` 只按标题文字精确匹配**（忽略首尾空格与大小写），不支持别名或模糊匹配。
- **附件粘贴**已有；**但没有**插件的"上下空一行"整理、没有"粘贴文件到指定目录"的独立设置、
  也没有把粘贴的图片按内容哈希去重（重复粘贴同一张图会产生多个副本）。
- **仓库名可配置未做**（M3 同步要用：服务端按 vault 名区分仓库）→ **M3 已做**：默认取仓库文件夹名（与 Obsidian 的 `vault.getName()` 一致），可在设置里显式覆盖。
- **Mermaid 增强未做**：当前只渲染，没有插件里的缩放 / 导出 SVG / PNG / 最大高度限制；
  主题固定用 mermaid 的 neutral，不跟随应用主题。
- **阅读视图未实现**。若要补，可复用 daily-sync 前端已验证过的
  `react-markdown + remark-gfm + rehype-highlight` 组合。
- **StateField 在每次事务都重算块级装饰**（含纯选区移动），现在要同时扫表格与 mermaid 块。
  当前文档量级下无感，但数万行或大量图表的仓库需要实测；若成为瓶颈，可改为只在文档变化或
  选区进出这些块时才重算。
- **大文档性能未验证**：装饰在视口内计算，但 `isActive` 与树遍历的开销尚未在数万行文档上测过。
- **外部删除当前笔记**：只提示「无法读取」，没有更明确的处理（例如提示并关闭编辑器）。
- **监听范围只含 `.md`/`.json`**：附件（图片等）变化不触发界面刷新。图片是显示时按需加载的，
  影响有限，但改名/删除后不会自动重载。
- **冲突提示只有两个选项**：没有"另存为副本"之类的第三种处理。

## 验证脚本相关的经验

- **GUI 测试不要在视口外点击**。720px 窗口下，文末的行可能在 y≈790（超出窗口），点击坐标
  会落到窗口外、光标不动，表现为"断言失败但代码没问题"。要么先滚动，要么改为断言装饰类名
  而不依赖点击。
- **DOM 选择器要限定在 `.cm-line` 内**。表格单元格与正文使用了相同的样式类（`cm-lp-link`、
  `cm-lp-code`），而表格作为块级 widget 排在正文之前，`querySelector` 会先命中表格里的那个，
  导致断言的"对象"根本不是要测的那一个。
- **收尾必须先关应用、再还原文件**。应用还开着的时候还原 fixture，它排队中的自动保存会把
  内容又写回文件，基线于是对不上。这个顺序错误是被"字节精确基线比对"抓到的——断言文件的
  哈希不只是为了验证编辑器，也顺带守住了测试流程本身。
- **React 的重渲染是异步的**。测试里不能在同一个同步表达式里"点按钮 → 立刻查面板"，
  必须分步并等一拍（`gui-paste.mjs` 的 `setSettingsOpen` / `setPasteEnabled`）。
  受控输入同理：直接改 `.value` 不会触发 onChange，要用原生 setter + `input` 事件。
- **"文字在 DOM 里"不等于"已经渲染"**。CodeMirror 会渲染视口外的一段余量，所以用
  "文本是否出现"来判断要不要滚动会提前结束，后面的断言全部落空——加个额外语法段落后
  布局一变就复现了。断言元素时必须滚到**目标元素真的出现**为止
  （`scrollUntil`），别用文本判断。
- **测试里不要假设初始状态**。主题默认是"跟随系统"，所以初始主题取决于机器；
  第一版测试假设初始是浅色，在深色机器上直接失败。显式指定要比假设可靠。
- **不要用 `&` 在工具调用里启动 GUI 应用**：跨调用杀进程会因权限上下文不同而"拒绝访问"，
  留下占用 WebView2 数据目录的僵尸实例。启动与清理放在同一个脚本里（如 `verify-gui.sh`
  的 trap）才可靠。
- **关闭应用要先走 CDP 优雅退出、等它退完、再兜底 `taskkill`**。直接强杀会打断 WebView2
  的收尾流程，进程会卡在"终止中"状态，此后连 `taskkill /F` 都返回"拒绝访问"，只能重启或
  管理员结束（本项目踩过多次）。而且**正在退出的进程是无法再被强杀的**，所以 `close_app`
  现在会先轮询最多 10 秒等它自己退出，实在不退才强杀。
- **GUI 测试用独立 identifier 构建**。`verify-gui.sh` 现在以
  `--config '{"identifier":"com.quicknote.gui-test"}'` 构建，使 WebView2 使用独立数据目录。
  这解决两件事：测试不再读写你日常使用的应用配置；即使本机残留了卡死实例把正式数据目录
  锁坏，测试照样能跑。**踩到的具体现象**：卡死实例把 `%LOCALAPPDATA%\com.quicknote.app\EBWebView`
  锁住后，新实例的 WebView2 根本初始化不了（进程内存只有 35MB，调试端口始终不开），
  表面症状是"应用启动失败"，实际是数据目录被占用。
