## 一、环境搭建（本机一次性）

安装清单：Rust 4 个 Android target（rustup）、Android SDK cmdline-tools +
platform-34 + build-tools 34 + **NDK r27**（装在 `H:\develop\android-sdk`）、
**JDK 21**（Temurin，`H:\develop\jdk-21.0.12.1+1`；JDK 23 与部分 Gradle/AGP 组合有
兼容风险，21 是 AGP 的 LTS）。

### 本机特有坑一：非 ASCII 用户名弄断 NDK 链接与 Kotlin 编译

Windows 用户名「一切随缘」是非 ASCII，炸了**两处**：

1. **Rust 链接**：NDK 的 `ld.lld` 打不开 `%USERPROFILE%\.rustup` 下工具链 rlib
   （报 `cannot open ... unspecified system_category error`，路径里的中文按 GBK
   传给了只认 UTF-8 的 lld）。
   - 先试了 **junction 镜像**（`C:\rustup-mirror` → 真实 `.rustup`）：**失败**——
     rustup 代理在解析工具链路径时 canonicalize，junction 被解开回真实路径，
     rustc 的 sysroot 依旧非 ASCII。
   - 最终方案：`.rustup` 整体 **mv 到 `C:\rust\rustup`**（C: 同盘改名，瞬时零复制，
     H 盘只剩 1.1GB 放不下 2GB 拷贝），旧位置留同名 junction 兼容 + `setx RUSTUP_HOME`。
2. **Kotlin 编译**：tauri 的 Kotlin 源码在 `.cargo` 注册表缓存里（C:），项目在 H:，
   Kotlin 守护进程 `relativize` 抛 `different roots`；同时用户名被转成
   `\u4E00...` 找不到文件。
   - 解法：**`H:\cargo-mirror` junction → `%USERPROFILE%\.cargo`**。Kotlin 的
     `Path.relativize` 是纯字符串操作（不解析 junction、不 canonicalize），
     于是两个路径都在 H: 根下（同根）且全 ASCII，两个问题一次解决，且不动文件
     （.cargo 628MB，H 盘塞不下）。

两条环境变量已 `setx` 永久化（`RUSTUP_HOME=C:\rust\rustup`、
`CARGO_HOME=H:\cargo-mirror`）。**CARGO_HOME 必须全环境统一**：cargo 的构建指纹里
含源码路径，桌面与 Android 构建若用不同 CARGO_HOME，每次切换都会全量重编；
`scripts/android-env.sh` 为任何新环境兜底（构建前 `source` 它即可）。

### 本机特有坑二：H 盘满导致构建中断（已解决）

`H:` 一度只剩 190MB，链接产物写入报 `os error 112 磁盘空间不足`。根因之一是本机原有
`H:\develop\Android`（旧 Android Studio + Sdk + AVD，36GB）与本次新装的
`H:\develop\android-sdk` 并存——旧 Sdk 没有 NDK，确认无用后整体删除，`H:` 恢复
48GB 可用，构建随即通过。

## 二、代码改动清单

### Cargo.toml —— 依赖按平台分层

```toml
# 桌面（非 android/ios）：updater 插件 + ureq(native-tls)
# 移动（android/ios）：ureq(rustls)
# Windows：webview2-com + windows-core（COM 内存优化）
```

关键约束：**Cargo.toml 的 target 段不认识 tauri-build 注入的 `cfg(desktop)/cfg(mobile)`
自定义 cfg**（依赖解析发生在 build script 之前），必须写 `target_os` 布尔表达式；
源码内部才可以用 `cfg(desktop)/cfg(mobile)`。

### src-tauri/src/net.rs —— TLS provider 按平台

- 桌面：`NativeTls`（Windows = SChannel，维持原行为）；
- 移动：`Rustls` + `RootCerts::WebPki`（Android 系统信任库不在 rustls-native-certs
  期望的标准路径上；WebPki 是 ureq 3 的默认根证书集，对 daily-sync 的
  Let's Encrypt 证书足够）。

### src-tauri/src/lib.rs —— cfg 隔离 + 移动端默认仓库

- `configure_webview2()`、`data_dir::configure_webview_data_dir()`：`#[cfg(desktop)]`；
- WebView2 COM 内存档位（`set_memory_usage_target` 与整个 setup 逻辑）：`#[cfg(desktop)]`；
  移动端 setup 暂为空（内存治理在 A3 接 Activity 生命周期）；
- **updater 插件**改为条件注册（Builder 先构建再链式），依赖也只在桌面编译；
- 新增命令 **`default_vault_dir`**：移动端返回 `app_local_data_dir()/vault`
  （不存在则创建），桌面恒返回 `None`——桌面仓库永远由用户选择，语义不混。

### src-tauri/capabilities —— 按平台拆分

`default.json` 拆成 `desktop.json`（windows/macOS/linux，原内容 + `platforms` 字段）与
`mobile.json`（android/iOS，仅 `core:default` + opener/dialog/notification 默认集）。
不拆分的话移动端构建会因引用桌面专属权限（updater/window 系列）校验失败。

### 前端

- 新增 `src/lib/platform.ts`：`isMobile()`（UA 判定，同步、启动即可用）与
  `hasHover()`；约定 **UI 代码禁止散落 userAgent 判断**，能力开关收敛于此；
- `api.ts` 增加 `defaultVaultDir()` 封装；
- `App.tsx` 启动链插入移动分支：`startupVault → (移动端) defaultVaultDir →
  localStorage`——移动端固定私有仓库且优先于 localStorage（防陈旧路径）；桌面链路不变；
- `index.html` viewport 增加 `viewport-fit=cover, interactive-widget=resizes-content`
  （键盘弹出时不遮挡光标、刘海屏安全区；桌面无影响）。

### gen/android 与脚本

- `src-tauri/gen/android` 按 Tauri 惯例**入库**（模板自带 .gitignore 排除 build 产物
  与密钥文件）；`ndkVersion`/SDK 版本由模板固定（NDK 27.0.12077973 / compileSdk 36）；
- `scripts/android-env.sh`：Android 构建环境一键 export（含两条本机坑的说明）。

### 模拟器验证（本机即可测，已通过）

环境：`sdkmanager` 装 emulator + `system-images;android-35;google_apis;x86_64`，
AVD（Pixel 6 profile）放 **`H:\android-avd`**（ASCII 路径）。又一个环境坑：本机进程
环境残留 `ANDROID_SDK_HOME=H:\develop\Android\AVD`（旧 Android Studio 设置，目录已
删），模拟器因此反复报 `feature-flags.protobuf.lock` 创建失败死循环——会话内
`unset ANDROID_SDK_HOME` + `ANDROID_AVD_HOME=H:\android-avd` 绕开
（`android-env.sh` 已固化）。WHPX 硬件加速可用（`HypervisorPresent=true`），
冷启动约 25 秒。

自动验收（`scripts/gui-android-smoke.mjs`，CDP 经 `adb forward tcp:9222` 接入，
模式与桌面 gui-*.mjs 相同）：

- **阶段一**：vault 指向 `/data/user/0/com.quicknote.app/vault`（私有沙箱）→
  UI 点「＋日记」→ 内联输入「冒烟测试」回车 → 日记创建并打开 → 插入中文探针
  （含 `**加粗**`、`` `代码` `` 行内语法）→ 自动保存落盘 → `run-as` 读文件断言
  **中文与行内语法原文完整（字节精确往返在 Android 成立）**；
- **阶段二**：`am force-stop` 杀进程重启 → 磁盘内容完整；
- 系统状态：WebView 124（≥111 的 color-mix/cqw 要求满足）、状态栏
  「同步未启用 · 1 篇」、日历「当天日记(1)」与统计「本月 1 天」联动正常、深色主题正常。

调试句柄变化：`window.__qnView` 从「仅 DEV」改为**无条件暴露**（editor.ts）——
移动端没有 dev server，验收必须有它；CDP 只能经 adb/调试参数进来，无实际风险。

冒烟脚本踩过的坑（留作 mobile GUI 验收的公共经验）：

1. 右栏「日历/目录/统计」页签的类名也含 `tab`，**不能**用 `[class*=tab]` 判断
   「有笔记打开」；要用编辑器文档内容（含今日标题）作判据；
2. 文件名带空格时 `adb shell` + `execSync` 会把引号丢在 Windows→adb 两层拆参里，
   必须 `execFileSync("adb", ["shell", 整条命令])` 单参数传递；
3. React 受控输入要用原生 setter + `dispatchEvent(new Event('input'))` 填值
   （与桌面脚本同款手法），Enter 用 `KeyboardEvent` 派发；
4. `.cm-content` 与 `__qnView` 在无标签时就存在（空状态遮罩之下），插入事务会
   落进孤儿视图并被后续 `setState` 冲掉——插入前必须等真实笔记打开。

**留给用户的一项**：在模拟器窗口（或真机）用手打中文输入法（Gboard/搜狗）做
组合输入测试——`Input.insertText` 级别的自动化无法替代真实 IME 组合路径。

- **真机验证清单（发布前，用户）**：
  1. 安装 debug APK（`src-tauri/gen/android/app/build/outputs/apk/universal/debug/app-universal-debug.apk`）；
  2. 启动自动进入空仓库（无仓库选择框）；
  3. 新建笔记，输入中文（Gboard/搜狗各试）：组合输入、退格、光标点击定位；
  4. 键盘弹出时光标不被遮挡；
  5. Live Preview 渲染正常、深浅主题切换；
  6. 杀进程重开，内容还在（自动保存落盘）。

## 五、已知问题 / 遗留

- 桌面 `cargo fmt` 会重排历史文件（仓库原本未完全 fmt-clean）——本次已回滚未改动文件，
  A1 起考虑一次性全库 fmt 落地；
- H 盘空间告急（1.1GB），A1 的 Gradle 缓存会继续增长，建议迁移或清理；
- updater 前端回退链（插件失败 → GitHub API 提示发布页）在移动端天然生效，
  应用内下载 APK 的更新流程排 A3。
