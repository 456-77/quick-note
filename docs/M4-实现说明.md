# M4 实现说明：增强功能

M4 把 quick-daily-note 插件里剩余的应用级功能搬进桌面端：**周回顾、粘贴语言识别、
图片工具栏、Mermaid 增强、全局背景、定时提醒 + 系统通知、天气**。与 M2/M3 同一条
原则——功能对齐插件，数据口径与插件共用，能移植的代码直接移植，但**移植不等于照抄**：
桌面端有桌面端的结构（Rust 命令、CM6 widget、React 状态），Obsidian 的 DOM 钩子
（MutationObserver、`app.metadataCache`）全都要换成本项目的等价物。

移植清单（自 `daily-sync/quick-daily-note` 插件）：

| 功能 | 移植来源 | 落地形式 |
|---|---|---|
| 语言识别 | `languageDetect.ts` | **原样复制**（纯函数，零依赖） |
| 周回顾 | `insertWeeklyReview` / `WeekReviewModal` | 纯函数 + React 选周弹窗 |
| 提醒 | `setupReminderTimer` / `checkReminders` | 纯函数 + `setInterval` + 系统通知 |
| 天气 | `fetchWeather` / `appendWeatherToNote` | 纯函数 + Rust HTTP 通道 |
| 背景设置 | `applyBackground`（bg* 十键） | 本机设置 + CSS 变量层 |
| Mermaid 增强 | `wrap` / 缩放 / 导出 | 移进 CM6 widget 的 toDOM |
| 图片工具栏 | `enhanceImage` / 三个 Modal | widget 工具栏 + React 弹窗 + 复用现有 Rust 命令 |

## 一、与插件的三处刻意差异

### 1. Mermaid 导出保存进仓库，不走浏览器下载

插件用 `<a download>` 把 SVG/PNG 落到浏览器下载目录。Quick Note 面临两个问题：
WebView2 对 blob URL 下载的支持不确定；而且知识系统的导出物散在下载文件夹里，
本来就不如跟着库走。所以导出用现有的 `write_binary`（允许覆盖、逐级建目录）把
`笔记名-mermaid-N.svg/png` 写进**当前笔记同目录**（没开笔记就仓库根）。

PNG 导出仍要处理 mermaid 的老问题：文字默认用 `foreignObject` 承载 HTML，而 SVG
作为 `<img>` 加载时浏览器不渲染其中的 HTML——PNG 会丢掉所有文字。插件的处理
（克隆时把 foreignObject 换成普通 `<text>`，位置/字号取自原始 DOM 的实时布局）
原样移植。画布底色取自当前主题的 `background-color`，透明底在浅色查看器里看不见白线。

### 2. 背景不支持视频动态壁纸

插件的背景是十一个键（开关、路径、不透明度、模糊、亮度、对比度、水平/垂直位置、
缩放、适配），Quick Note 全部保留；唯独**不移植视频壁纸**。技术选型第八节早就
写明视频是内存杀手（常驻解码 + 一份全屏纹理），对一个把 `--disable-gpu` 都开了的
应用来说是反向优化。这是 M4 唯一主动砍掉的插件功能。

背景层实现是 `#qn-bg-layer`（fixed、`pointer-events:none`、z-index 0），界面内容
在其上（z-index ≥ 1）。启用时 `<html>` 挂 `qn-bg-on` 类，由 CSS 把顶栏/侧栏/编辑器
卡片改成 `color-mix` 半透明——层自身不接收事件也不盖住任何内容，所以**窗口拖拽不受
影响**（插件当年在这里踩过坑：覆盖层与标题栏重叠会让拖拽失效，它的解法是把背景层
起点下移一个标题栏；Quick Note 的层在内容之下，问题不存在）。

### 3. 天气在落盘前并入内容，不做"先建再补写"

插件是先建日记再异步抓天气、抓到后 `vault.modify` 补写一行。Quick Note 的文件监听
与同步都盯着每次落盘，多一次写入就是多一次回声过滤。所以 `openDaily` 在**第一次
`writeNote` 之前**就 await 天气（8 秒超时、失败静默），天气行随正文一次落盘：
文件只写一次，监听器、同步引擎都看不到任何中间状态。

## 二、设置键的归属：跟着插件走

插件把**除背景外的全部设置**写进共享的 `quick-daily-note.json`（背景十键才是每设备
独立的 `DEVICE_LOCAL_KEYS`）。Quick Note 保持同一种归属：

- **写入库内配置**（补丁式写回，`OWNED_KEYS` 扩到 15 个）：`autoDetectCodeLang`、
  `todoReminderEnabled/Time`、`checkReminderEnabled/Time`、`weatherEnabled/City`。
  两边换用不用设两次，同步一开自动一致。
- **存本机**（localStorage `Settings`）：背景十键。背景是纯观感偏好，同步它只会让
  每台机器被迫接受同一张图。

提醒时间串保持 "HH:mm" 零填充格式做**字典序比较**（零填充下字典序即时间序，与插件
同一套）；读到非法值（如 "8:00"）时兜底为默认时间——非零填充的字典序会错格，宁可
回默认也不能错。布尔键沿用 `=== true` 的严格解析，`autoDetectCodeLang` 例外：插件
默认开启，所以用 `!== false`（读旧配置文件时没有这个键，应当开而不是关）。

## 三、定时提醒：语义在初始化里

插件的行为是"启用时若当天时间点已过，则当天不再提醒（从次日生效）"。读它的源码
会发现这条语义**不在轮询判定里**，而在 `setupReminderTimer` 的启动初始化里：
启动时 `nowTime >= todoReminderTime` 就把当天的已提醒标记置位。纯函数 `dueReminders`
只回答"此刻该不该响"；`initialFiredMarks` 单独实现初始化语义。两者都在 Node 里
逐分支断言（`verify-m4.mjs`）：到点触发一次、当天不重复、次日复位、已过不补、
非法时间不误触、开关关闭不触发。

通知用 `tauri-plugin-notification`（Windows 走系统通知中心）。权限没批或插件不可用
时**静默降级**为界面提示——提醒不该报错。"检查未完成待办"这条沿用插件的克制：
当天一条未完成都没有就不打扰。

## 四、周回顾

输出格式与插件**逐行一致**（`## 本周回顾（9月15日 ~ 9月21日）` → 日记汇总 →
待办完成 → 待办未完成），包括几个容易走样的细节：

- 字数口径是**去空白后的长度**（`wordCount`），与统计、插件同源；
- 待办按日遍历保持录入顺序，多行待办压平成 `a / b`（避免拆断复选框行）；
- 墓碑（`deleted`）不进统计——顺延后的源日期还有墓碑，混进来就会重复计数；
- 非本周的标题用 ISO **周号年**：`moment.format("GGGG-[W]WW")`，`2027-01-01`
  属于 `2026-W53`，用 `YYYY` 每年跨年必错一次。

入口有两个（命令面板）：「生成本周回顾」直接插；「生成选定周的回顾」先开 12 周
列表（本周在前，跨年不错格）。插入位置是当前笔记的光标处，前后补空行让标题独立
成段——补位规则与代码块粘贴共用同一个 `blockInsertPadding`（行中/行尾/行首/空行
四种情形各不同）。

## 五、粘贴语言识别

`languageDetect.ts` 是插件里的独立纯函数文件，**原样复制**（只加了文件头注释）。
识别口径两边完全一致：语法特征加权打分、单规则最多按 2 次命中、弱特征设贡献上限、
多行阈值 4 / 单行阈值 4.5（单行只有特征非常明确才出手，避免把普通文字包进围栏）。
JSON 之外，整段可解析的直接判定为 json。

接线在 CM6 的 `domEventHandlers`，排在附件粘贴**之后**（剪贴板里有文件时轮不到它）。
三种情况不干预：整块复制了已带围栏的代码；光标已在围栏块内（逐行数围栏，与插件同一
套规则）；识别不出语言。语言名就是代码块语言标识（`typescript`、`cpp`、`mermaid`…）。

## 六、图片工具栏

本地图（wiki 嵌入与 Markdown 两种写法）悬停出工具栏：**复制 / 裁剪 / 重命名 / 删除**。
动作经 `LivePreviewContext` 注入（同一个可变对象约定，App 启动后填字段），widget 只
负责发起，落盘与弹窗都在 App 层。

- **复制**：`readBinary` → 非 PNG 先经画布转码 → `navigator.clipboard.write`。
  Chromium 剪贴板只保证认 `image/png`，所以统一转 PNG。
- **裁剪**：React 弹窗（拖拽选区 → 松开出现裁剪钮 → canvas 裁切 → PNG 覆写），
  与插件 ImageCropModal 同一套交互与"选区 < 2px 视为误触"阈值。覆写后
  `bumpImageEpoch()`——图片 URL 带上代际参数，所有已渲染的同图立即重载，
  绕开 asset 协议的缓存。
- **重命名 / 删除**：复用侧栏同一套流程（`renameEntry` / `.trash`），**但这次修了
  Rust 侧一个既有 bug**——见下。

### 顺带修掉的既有 bug：附件重命名丢扩展名

`rename_entry` 原来的逻辑是"名字缺 `.md` 就补 `.md`"——对笔记是对的，但对图片意味着
`架构图.png` 改名 `架构图` 会变成 `架构图.md`，文件直接用废。现在非 md 文件缺扩展名
时补**原扩展名**，且附件的 wiki 嵌入（`![[图.png]]` 本来就带扩展名）同样按文件名
匹配更新引用。新增集成测试 `renames_attachment_keeps_extension_and_updates_embeds`
锁住这两个行为。

### 删除并清理引用

删除前用 `search_vault(文件名)` 圈定候选笔记（文件名是足够独特的关键词，含空格也
没问题），再对每篇做**精确**的引用清理：只认 `![[…]]` 与 `![…](…)` 两种写法、围栏
代码块里的内容不处理、引用删空的行整行移除、无引用返回 null（跳过写盘）。这套
规则自插件的 `removeImageLinksFromNote` 移植成纯函数（`imageOps.ts`）。

## 七、验收

`verify-all.sh` 新增第 12 步 `verify-m4.mjs`（86 项断言）：语言识别的正反例
（中文散文、英文清单绝不能被包成代码块）、周回顾格式逐行比对、提醒的全部分支、
天气文案与插入位置、引用清理的围栏跳过与整行移除、共享配置的补丁式写回
（**插件专有键原样保留**——这条又断言了一遍，因为它是最容易在扩展键时写坏的地方）。

Rust 侧：附件重命名测试进 `create.rs`（`renames_attachment_keeps_extension_and_updates_embeds`）。

GUI 层（`verify-gui.sh`，426 项断言全绿）随 M4 顺手修了两处测试自身的缺陷：

1. **文末滚动偶发失败**（`gui-livepreview.mjs`）：打开文档后一次性
   `scrollTop = 1e6`，会被 CM6 当时偏小的高度估算钳制在半路，断言"文末引用行
   进入渲染范围"就随机挂掉。**用 M3 基线代码复现过同样的失败**——是既有缺陷，
   不是 M4 引入。修法是循环赋值直到 scrollTop 顶到真实底部（每次等 120ms 让
   估算稳定）。顺带的教训：判定"是不是我改坏的"，stash 后重建基线复跑是最短路径。
2. **键序断言升级到 M4 口径**（`gui-daily.mjs`）：原断言硬编码"pastedImageFolder
   是唯一新增自有键且在末尾"。M4 把自有键从 9 个扩到 15 个，fixture 里没有的新增键
   变成 4 个（pastedImageFolder、autoDetectCodeLang、checkReminder*）。不变量
   本身没变——fixture 键相对顺序原样、fixture 之外的键全部按序追加在末尾——
   断言改为按这份清单核对。

设置面板新增控件时守住两条 DOM 契约（`SettingsDialog.tsx` 顶部注释）：
第一个 checkbox 仍是「粘贴时保存附件」、第一个 `input[type=text]` 仍是
「附件保存目录」。「背景图片路径」在 appearance 分区（DOM 序在 daily 之前），
用 `type="search"` 规避——与顶部设置搜索框同一套手法。

提醒要等真实时间点、天气要外网、背景是纯观感：这些运行时条件刻进了纯函数
测试能覆盖的部分（`verify-m4.mjs` 的分支断言），GUI 层不伪造时钟与网络。

## 八、0.4.2 体验修复（M4 验收期间发现的问题）

M4 双绿之后又做了一轮体验修复，全部进了同一层验收：

### 编辑区 Obsidian 化与代码块全出血

用户反馈编辑区"像嵌套网页"——卡片容器（圆角/阴影/独立底色）删除后，标签栏并入
编辑区、内容 900px 居中。**代码块突破宽度**的第一版用负外边距 `+128px`，在窄
窗格里必然横向溢出：`.cm-scroller` 的水平滚动条随代码块进出视口反复出现/消失，
clientHeight 抖动，滚动锚定跟着拉扯滚动位置——gui-rendering 的渐进滚动因此在中途
停摆（10 项失败）。第二版改用**容器查询**：`.cm-scroller` 设 `container-type:
inline-size`，代码块 `width: 100cqw` + `margin-left: calc((100% - 100cqw) / 2)`——
铺满滚动容器、永不溢出，宽窗格里真正突破 900px，窄窗格里自动退化，代码文本
用同一条公式与正文左缘对齐。教训：**编辑器布局里任何会引起页面级横向滚动条
出现/消失的样式都是滚动稳定性的敌人**。

### 待办 ⋯ 点了没反应

根因不在按钮：右栏卡片 hover 时 `transform: translateY(-1px)`，而 transform 使
元素成为 `position: fixed` 后代的**包含块**——面板里的 ⋯ 菜单按视口坐标定位，
坐标系却变成了卡片，直接飞出屏幕。修复 = 去掉 hover 位移（层级感交给阴影）。
顺带把添加/编辑输入换成多行 textarea（Enter 提交、Shift+Enter 换行、随内容
长高），⋯ 按钮改悬停悬浮显示。

### 表格三连

1. **data-row 写死**：`buildRow` 给所有数据行都写 `data-row="1"`，渲染态里编辑
   任何数据行都写回第一行。一行 `forEach` 索引的修复，加了 GUI 回归断言。
2. **formatTable 右对齐降级**：右对齐的分隔行标记被输出成**前导**冒号（`:---`），
   而 `alignOf` 把前导冒号读成 left——右对齐列在任何一次对齐/编辑后静默变左。
   改为尾随冒号（`---:`），`verify-tables.mjs` 补了幂等断言。
3. **选不中整张表**：单元格各自是编辑宿主，浏览器把选区钳在单格里（Obsidian
   用自研表格模型才做得到跨格选区）。解法是 **Ctrl+A 两段式全选**：第一次
   全选本格，第二次升级为选整张表（preventDefault + 手动 Range——原生
   select-all 的选区会被 CM 的 DOM 观察者重置，靠不住），复制时拦截 `copy`
   以选中文本为准。期间试过把表格宿主设为 `contenteditable` 来支持跨格拖选，
   **实测 Chromium 会把焦点给表格而不是单元格**，整套就地编辑失效——撤销，
   并把这条写进注释。

### 其他

- **智能粘贴**：`smartPaste` 取代早期的 codePaste——换行符规范化始终开启
  （CRLF 剪贴板进 LF 文档不留裸 `\r`），HTML `<table>`/TSV 自动转 Markdown
  表格（`pasteTransforms.ts`，100 项纯逻辑断言），代码围栏受开关控制。
- **隐形按钮拦截点击**：表格 ＋行/＋列 按钮 `opacity: 0` 但仍可点击，自动化
  点击/双击的落点恰好压上时会误触结构操作（实测真的发生了）。统一加
  `pointer-events: none`（显示时恢复），与待办 ⋯ 同一套模式。
- **测试侧**：CDP 按键事件的修饰键是 `modifiers: 2` 位掩码，`control: true`
  不是有效参数（静默无效，DOM 事件里 ctrl=false）；CM6 渐进滚动到文档深处
  会被 widget 高度估算与滚动锚定拉扯，scrollUntil 类 helper 要循环到断言成立
  而不是固定步数。
